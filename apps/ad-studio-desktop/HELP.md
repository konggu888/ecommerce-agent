# AI 商品广告工厂（桌面版）帮助文档

> 本文是项目的长期功能说明书。以后每增加、修改或修复一项用户可见功能，都必须同步更新本文件的“功能总表”和“更新记录”。

## 1. 产品定位
AI 商品广告工厂是 Windows 本地桌面软件：
- 本地计算设备负责能高效完成的编排、素材管理、视频加工、FFmpeg 后处理和最终合成；系统自动检测硬件能力。
- 云端只负责本地难以生成的高质量素材/视频任务。
- 本地资产库优先复用；没有合适素材时才允许自动生成。
- 生成后的可复用素材进入本地永久资产库。
- 项目工程、成片和资产库分开储存。
- 云端成本在真正调用前预估并展示。

## 2. 完整工作流
商品链接 → 商品资料采集 → AI商品理解 → 卖点提炼 → 人群与痛点 → 广告策略 → 广告强度 → 视频形式 → 剧本 → 分镜 → 每镜头资产需求 → 项目级成本预估 → 用户预算确认 → 本地资产匹配 → 缺失资产按需云端生成 → 资产永久入库 → 云端镜头生成 → 本地硬件/FFmpeg后处理 → 字幕/音频/BGM → 最终拼接。

## 3. 创建广告项目与预算
用户可以为每个项目输入自己的预算，例如 ¥3、¥5、¥10、¥50。

创建前显示：
- 视频生成费用
- 演员生成费用
- 场景生成费用
- 商品素材生成费用
- 本地处理费用
- 总费用

如果总费用超过本次预算：
- 明确显示超预算。
- 明确询问是否继续。
- 不自动换模型。
- 不自动降低质量。
- 不自动减少镜头。
- 不自动改变广告方案。

用户取消：
- 不保存新项目。
- 不开始后续云端素材生成。
- 不产生后续云端素材调用费用。

## 4. 成本计算
- 视频成本按计划镜头数 × 当前视频Provider价格。
- 演员/场景/商品素材成本按本地缺失的唯一资产需求计算。
- 同一资产需求跨多个镜头只计一次。
- 价格来自本机Provider配置；占位价格不能冒充供应商正式报价。
- 实际生成后记录实际发生费用。

## 5. 本地资产库
资产类型包括演员、场景、商品素材、BGM。

匹配原则：
**本地优先 → 可复用直接复用 → 可加工则本地加工 → 没有合适素材才自动生成。**

AI生成的新资产：
- 自动保存到本地资产库。
- 获得稳定资产ID。
- 后续项目优先复用。
- 避免相同演员/场景反复付费生成。

## 6. 资产库可自定义硬盘
为了避免系统盘爆满，资产库支持独立硬盘目录。

例如：
- D:\AI广告素材库
- E:\电商资产库
- F:\广告工厂\Assets

桌面端入口：
**💾 资产库位置 → 选择硬盘目录 → 保存并切换**

资产库与项目工程目录分离。切换位置不会自动删除旧资产，也不会偷偷搬迁旧资产。

## 7. 多模型AI创意引擎
当前独立路由：
- 商品理解
- 卖点提炼
- 人群与痛点
- 广告策略
- 广告强度判断
- 视频形式判断
- 剧本
- 分镜
- 素材选择

默认GPT；不同功能可以使用不同模型，也支持本地模型。

### 多创意方案
同一个商品可以一次生成 1 或 3 个彼此明显不同的广告方案。
- 每个方案仍经过独立的商品理解、卖点、人群、策略、强度、视频形式、剧本、分镜、素材选择流程。
- 系统会把前一个方案的打法传给后续方案作为“避免重复”的约束，而不是固定把某个行业硬套成某一种视频。
- 用户可以在同一个项目中切换方案，再分别生成镜头和成片。
- 方案数量为 3 时，系统目标是测试三个不同的广告机制，而不是只改标题或换几句文案。
- 云端视频/素材成本按当前选中的方案单独预估；切换方案后需要重新确认当前方案成本。

## 7.1 多版本创意分析（投放前）
“🧠 创意方案分析”只分析已经生成的创意方案本身，不假设用户要投放到哪个平台，也不凭空产生 CTR、CVR、CPA、ROAS 等数据。

分析内容包括：
- 每个方案到底在测试什么创意轴。
- Hook/开场、核心策略、核心卖点、证明方式、行动引导和目标人群的差异。
- 两两方案的结构差异，避免只改字幕、颜色等表面元素却宣称是不同打法。
- 下一轮应该继续强化或拉开哪些创意差异。

真实投放数据是独立的可选层。只有用户实际投放后主动提供对应平台的真实数据，系统才记录并计算投放指标；系统不会自行决定抖音、淘宝、拼多多、小红书或京东，也不会把模拟数据当成真实数据。
在投放前，系统还会做一次确定性的“创意实验设计审计”：区分核心机制变化与表层文案变化，并检查两两方案是否只改变一个核心机制。它只评价“这个实验设计是否干净”，不评价哪个平台、哪个方案实际赚钱。

## 8. 本地硬件能力 / FFmpeg
## 8.1 本地实拍视频 AI 自动剪辑

桌面端现在有独立的“用户拍摄素材”工作流：
**商品资料 + 用户实拍视频文件夹 → 关键帧视觉分析 → 卖点/商品/人物/场景/重复/遮挡/糊片等判断 → AI剪辑导演 → 本地FFmpeg裁剪 → 后处理 → 成片**。

实拍分析不再只看文件名、时长和分辨率。系统会从每个可解析视频均匀抽取少量低分辨率关键帧；启用“支持图片/视频帧分析”的模型后，关键帧会作为视觉输入交给“素材剪辑导演”。视觉分析结果保存到项目的 `creative_plan.footage_visual_analysis`，后续剪辑导演再根据这些结果决定具体起止时间。

模型设置新增：
- **支持图片/视频帧分析**：实拍视觉分析必须打开。
- 默认 GPT 模型会预设开启；自定义本地/云端模型必须确认自身接口支持图片输入。

注意：当前分析粒度是“关键帧视觉分析”，不是把整段视频作为原生视频文件直接交给模型。口播逐字稿、逐帧动作识别、自动人声去废话仍需后续接入专门的视频理解/转写能力。

已接入：
- GPU检测
- FFmpeg检测
- NVENC硬件编码
- 画幅适配
- 裁切
- 缩放
- AI构图坐标执行
- 速度调整
- 转场
- 字幕烧录
- 人声/BGM混音
- 最终视频拼接
- 镜头版本化

支持9:16、1:1、16:9。

### 实拍重复镜头识别与最佳版本选择
视觉分析现在还会把同一拍摄动作/卖点的重复镜头进行分组，并比较清晰度、构图、商品展示完整度、动作完成度、口播质量和广告价值，输出最佳版本（`best_take`）及优先级（`take_rank`）。剪辑导演会优先使用最佳版本，避免同一镜头的低质量重复素材进入成片。重复素材不会因为“重复”就自动删除；只有明确判定不可用的素材才进入废片库。\n\n### 实拍废片自动归档
视觉分析完成后，系统会自动处理两类明确不可用素材：
- AI 明确返回 `usable=false` 的素材，例如明显糊片、严重遮挡、严重抖动或没有广告价值的素材。
- FFmpeg 无法解析的素材。

这些文件会从原实拍文件夹**移动**到同级的 `05_废片库/<项目ID>/`，不会直接删除；系统同时写入 `archive-manifest.json`，记录原路径、归档路径、原因和视觉标签。只有成功移动的文件才会从后续剪辑候选中剔除。若移动失败，原文件继续保留并进入后续流程。

桌面端顶部提供 **📹 实拍分析报告**。创建或打开实拍项目后，可直接查看每个素材的 AI 评分、是否可用、废片原因、画面标签、推荐片段和口播质量，以及总体建议时长和废片归档数量。

项目文件现在保存实际成本总额和分类汇总；生产执行统一入口写账，避免资产费用与视频费用重复记录。

混合路由现在增加实际执行层：只有已经被路由为“AI补镜头”的通用缺口才会调用生成器；执行前再次检查预算；商品事实、真实外观/功能/操作和真人表达会强制拦截。生成成功后只进入“待复核”，不会自动写入最终分镜；生成失败也不会伪装成成功。

## 2026-10-08：真人口播缺料处理调整
真人口播不足不再一律要求补拍。系统仍禁止 AI 冒充真人出镜、真人口播或真人声音；但在缺少口播素材时，可以生成不含真人表达的辅助图片、视频、B-roll 等画面来承接或支撑口播。辅助素材生成后仍需人工复核，不能自动视为真人证据。


## 2026-10-08：混合缺口已接入真实生成执行链

实拍缺口不再停留在“建议 AI 补镜头”层面。获准任务现在可以进入真实 Provider 执行桥：再次检查预算 → 根据能力路由选择本地/云端 → 调用视频或图片生成服务 → 写入 UsageLedger 费用账本 → 标记“待人工复核”。生成结果默认不得直接进入最终分镜。

安全规则保持不变：商品事实、真实外观、真实功能、真实操作等证据缺口禁止用 AI 冒充；真人口播缺料可以生成不含真人表达的辅助图片、视频或 B-roll，但禁止生成/冒充真人出镜、真人口播或真人声音。


## 2026-10-08：人工复核通过后才能纳入分镜

AI生成的缺口素材即使 Provider 返回成功，也只标记为“待复核”，不会自动改变当前分镜。只有人工把复核状态明确设为“已通过/通过”，系统才允许执行纳入分镜动作；纳入后会生成稳定的额外镜头 ID，并重新整理镜头序号。重复执行不会重复插入同一个镜头。


## 2026-10-08：已审核素材正式进入项目分镜

混合生成素材在人工复核通过后，现在可以通过项目生产层正式写入 `Project.shots` 并持久化。写入后会获得稳定的补镜头 ID、重新整理镜头序号，因此最终成片阶段可以像处理普通镜头一样消费该素材；未通过人工复核的素材仍不能进入项目分镜。

## 创意测试方案（投放前）

“创意方案分析”回答“几个版本有什么不同”；“创意测试方案”进一步回答“每一版到底在验证什么”。

输出结构：

**测试目的 → 版本设计 → 需要观察的真实结果 → 下一轮建议**

只定义测试，不虚构结果；不默认任何投放平台；不自动生成 CTR、CVR、CPA、ROAS。只有真实投放后提供对应平台的真实数据，才进入结果分析。


## 创意事实与质量检查

投放前检查商品资料、创意卖点、禁用词和高风险绝对化表达。没有商品证据的内容标记为待核验，不由AI自行补全。商品主体遮挡、画面事实和字幕一致性需要成片/分镜复核。


## 分镜事实复核

投放前可打开“🎬 分镜事实复核”。系统检查分镜文字与已提供商品卖点的对应关系；外观、遮挡、功能演示和字幕画面一致性必须实际查看分镜/成片确认。


## 成片视觉复核

“🎥 成片视觉复核”会把实拍关键帧视觉分析结果映射到各方案实际使用的素材，重点提示商品遮挡、模糊、抖动、不可用素材等风险。它不是虚构的效果数据，也不会把“需复核”自动改成通过。


## 最终成片交付质检与清单

最终安全闸门通过后，系统还会对实际输出文件执行机器质检：文件存在且非空、存在视频流、可读取时长和尺寸，并检查实际画幅是否符合本次要求。质检失败会删除不合格输出并阻止交付。通过后会在最终视频旁写入同名 JSON 交付清单，记录方案编号、画幅、实际镜头组成、安全闸门结果和媒体质检结果。


## 最终输出版本管理

成片通过全部检查后会标记为“可交付”。系统按“方案 + 画幅”保存最终输出历史，不同版本不会互相覆盖，可追溯每个版本的输出路径、时长、镜头数量和生成时间。


## 2026-10-09：最终输出历史键稳定化
最终输出历史以 `方案序号|画幅` 作为唯一键，例如 `2|9:16`，避免同一方案不同画幅互相覆盖；回归测试同步验证该复合键。
