# AI 商品广告工厂（桌面版）帮助文档

> 本文是项目的长期功能说明书。以后每增加、修改或修复一项用户可见功能，都必须同步更新本文件的“功能总表”和“更新记录”。

## 1. 产品定位
AI 商品广告工厂是 Windows 本地桌面软件：
- 本地计算设备负责能高效完成的编排、素材管理、视频加工、FFmpeg 后处理和最终合成；系统自动检测硬件能力。
- 云端只负责本地难以生成的高质量素材/视频任务。
- 本地资产库优先复用；没有合适素材时才允许自动生成。
- 生成后的可复用素材进入本地永久资产库。
- 项目工程、成片和资产库分开储存。
- 云端成本在真正调用前预估并展示。

## 2. 完整工作流
商品链接 → 商品资料采集 → AI商品理解 → 卖点提炼 → 人群与痛点 → 广告策略 → 广告强度 → 视频形式 → 剧本 → 分镜 → 每镜头资产需求 → 项目级成本预估 → 用户预算确认 → 本地资产匹配 → 缺失资产按需云端生成 → 资产永久入库 → 云端镜头生成 → 本地硬件/FFmpeg后处理 → 字幕/音频/BGM → 最终拼接。

## 3. 创建广告项目与预算
用户可以为每个项目输入自己的预算，例如 ¥3、¥5、¥10、¥50。

创建前显示：
- 视频生成费用
- 演员生成费用
- 场景生成费用
- 商品素材生成费用
- 本地处理费用
- 总费用

如果总费用超过本次预算：
- 明确显示超预算。
- 明确询问是否继续。
- 不自动换模型。
- 不自动降低质量。
- 不自动减少镜头。
- 不自动改变广告方案。

用户取消：
- 不保存新项目。
- 不开始后续云端素材生成。
- 不产生后续云端素材调用费用。

## 4. 成本计算
- 视频成本按计划镜头数 × 当前视频Provider价格。
- 演员/场景/商品素材成本按本地缺失的唯一资产需求计算。
- 同一资产需求跨多个镜头只计一次。
- 价格来自本机Provider配置；占位价格不能冒充供应商正式报价。
- 实际生成后记录实际发生费用。

## 5. 本地资产库
资产类型包括演员、场景、商品素材、BGM。

匹配原则：
**本地优先 → 可复用直接复用 → 可加工则本地加工 → 没有合适素材才自动生成。**

AI生成的新资产：
- 自动保存到本地资产库。
- 获得稳定资产ID。
- 后续项目优先复用。
- 避免相同演员/场景反复付费生成。

## 6. 资产库可自定义硬盘
为了避免系统盘爆满，资产库支持独立硬盘目录。

例如：
- D:\AI广告素材库
- E:\电商资产库
- F:\广告工厂\Assets

桌面端入口：
**💾 资产库位置 → 选择硬盘目录 → 保存并切换**

资产库与项目工程目录分离。切换位置不会自动删除旧资产，也不会偷偷搬迁旧资产。

## 7. 多模型AI创意引擎
当前独立路由：
- 商品理解
- 卖点提炼
- 人群与痛点
- 广告策略
- 广告强度判断
- 视频形式判断
- 剧本
- 分镜
- 素材选择

默认GPT；不同功能可以使用不同模型，也支持本地模型。

### 多创意方案
同一个商品可以一次生成 1 或 3 个彼此明显不同的广告方案。
- 每个方案仍经过独立的商品理解、卖点、人群、策略、强度、视频形式、剧本、分镜、素材选择流程。
- 系统会把前一个方案的打法传给后续方案作为“避免重复”的约束，而不是固定把某个行业硬套成某一种视频。
- 用户可以在同一个项目中切换方案，再分别生成镜头和成片。
- 方案数量为 3 时，系统目标是测试三个不同的广告机制，而不是只改标题或换几句文案。
- 云端视频/素材成本按当前选中的方案单独预估；切换方案后需要重新确认当前方案成本。

## 8.1 本地实拍视频 AI 自动剪辑

桌面端现在有独立的“用户拍摄素材”工作流：
**商品资料 + 用户实拍视频文件夹 → 关键帧视觉分析 → 卖点/商品/人物/场景/重复/遮挡/糊片等判断 → AI剪辑导演 → 本地FFmpeg裁剪 → 后处理 → 成片**。

实拍分析不再只看文件名、时长和分辨率。系统会从每个可解析视频均匀抽取少量低分辨率关键帧；启用“支持图片/视频帧分析”的模型后，关键帧会作为视觉输入交给“素材剪辑导演”。视觉分析结果保存到项目的 `creative_plan.footage_visual_analysis`，后续剪辑导演再根据这些结果决定具体起止时间。

模型设置新增：
- **支持图片/视频帧分析**：实拍视觉分析必须打开。
- 默认 GPT 模型会预设开启；自定义本地/云端模型必须确认自身接口支持图片输入。

注意：当前分析粒度是“关键帧视觉分析”，不是把整段视频作为原生视频文件直接交给模型。口播逐字稿、逐帧动作识别、自动人声去废话仍需后续接入专门的视频理解/转写能力。

已接入：
- GPU检测
- FFmpeg检测
- NVENC硬件编码
- 画幅适配
- 裁切
- 缩放
- AI构图坐标执行
- 速度调整
- 转场
- 字幕烧录
- 人声/BGM混音
- 最终视频拼接
- 镜头版本化

支持9:16、1:1、16:9。

### 实拍重复镜头识别与最佳版本选择
视觉分析现在还会把同一拍摄动作/卖点的重复镜头进行分组，并比较清晰度、构图、商品展示完整度、动作完成度、口播质量和广告价值，输出最佳版本（`best_take`）及优先级（`take_rank`）。剪辑导演会优先使用最佳版本，避免同一镜头的低质量重复素材进入成片。重复素材不会因为“重复”就自动删除；只有明确判定不可用的素材才进入废片库。\n\n### 实拍废片自动归档
视觉分析完成后，系统会自动处理两类明确不可用素材：
- AI 明确返回 `usable=false` 的素材，例如明显糊片、严重遮挡、严重抖动或没有广告价值的素材。
- FFmpeg 无法解析的素材。

这些文件会从原实拍文件夹**移动**到同级的 `05_废片库/<项目ID>/`，不会直接删除；系统同时写入 `archive-manifest.json`，记录原路径、归档路径、原因和视觉标签。只有成功移动的文件才会从后续剪辑候选中剔除。若移动失败，原文件继续保留并进入后续流程。

桌面端顶部提供 **📹 实拍分析报告**。创建或打开实拍项目后，可直接查看每个素材的 AI 评分、是否可用、废片原因、画面标签、推荐片段和口播质量，以及总体建议时长和废片归档数量。

## 2026-10-08：口播结果进入剪辑导演
素材剪辑导演现在会同时收到视觉分析与 `footage_transcripts`，因此后续可以依据实际口播内容和时间段选择/删除表达，而不是只看画面。

## 2026-10-08：修复转写 multipart 构造
修复口播转写请求的 multipart 换行构造，确保桌面端 Python 编译检查通过。

## 2026-10-08：实拍口播废话自动删除与多段裁剪
实拍剪辑导演现在可以依据带时间戳的口播转写，把一个原始视频拆成多个保留区间 ranges，跳过寒暄、重复、口头禅、停顿和与卖点无关的废话。生产层会逐段用本地 FFmpeg 裁剪后再拼接，镜头仍然只使用用户自己的实拍素材。若转写服务只返回粗粒度 segment，系统只在 segment 边界做安全裁剪，不假装具备逐词级切割。

- 2026-10-08：实拍分析报告表格新增“重复组/最佳版本”字段，用户可直接查看 AI 对重复镜头的取舍。

- 2026-10-08：实拍分析报告新增“素材排名/综合分/AI评分”，综合分只用于排序，不覆盖 AI 原始评分；排名同时考虑最佳版本、口播质量、画面标签和重复镜头惩罚。


## 2026-10-08：实拍素材覆盖审计
素材排名完成后，系统增加一次本地确定性“覆盖审计”，不产生新的 AI 调用：从创意方案卖点与视觉分析的卖点标签建立卖点→素材映射，选出开场候选，并检查创意分镜要求的商品特写、演示、真人/场景、口播等关键镜头是否有真实实拍证据。缺失项只标记为“待补拍”，不会虚构素材。最终剪辑导演收到该审计结果后，允许唯一覆盖重要卖点的低排名素材优先于纯排名更高但重复的信息。


## 2026-10-08：最终分镜复核
素材剪辑导演生成 footage_plan 后，桌面端再做一次本地确定性复核：给最终镜头补充素材排名、综合分、重复组和已覆盖卖点，并检查开场候选是否真正进入成片、重要卖点是否在最终分镜中漏掉、重复拍摄组是否被重复使用。复核结果保存到 creative_plan["footage_selection_audit"]，不会重新调用 AI。


## 2026-10-08：实拍素材缺口处理
实拍素材覆盖审计后新增“素材缺口处理”结果。商品事实、细节、操作和演示等缺口统一标记为“待补拍”，避免用生成画面冒充真实商品证据；当前用户拍摄素材模式没有接通视频生成链，因此通用缺口标记为“待补素材”，不会把接口当成已生成能力。结果保存于 creative_plan["footage_gaps"]。


## 2026-10-08：实拍缺口分类输入兼容修复
修复“素材缺口处理”对覆盖审计结果的兼容性：即使缺失卖点只有名称列表、没有同步的卖点详情，也会保留为“待补拍”，不会被静默丢弃。新增回归测试覆盖该数据形态。


## 2026-10-08：实拍缺口任务清单
覆盖审计后的缺口现在会进一步转换成“补素材任务清单”，保存于项目 creative_plan["footage_gap_tasks"]。任务包含处理方式、优先级、缺口、关联卖点、具体补拍/生成要求和验收标准。桌面端新增“📋 补素材任务”入口；该报告只读取已有结果，不产生新的 AI 调用。当前实拍模式仍不自动执行拍摄或生成。


## 2026-10-08：实拍素材重新分析
新增“🔄 重新分析实拍素材”按钮。用户完成补拍后将新视频放回原素材文件夹即可重新扫描；系统重新执行视觉分析、废片归档、可选口播转写、素材排名、覆盖审计、缺口任务编排、AI剪辑方案和最终分镜复核。重复点击可继续迭代，直到素材覆盖满足成片要求。该过程会真实调用已配置的视觉/剪辑模型，不把缺失素材伪装成已存在素材。

## 2026-10-08：AI 强制推进前状态检查
以后 AI/Codex 每次收到“继续/推进/下一步”等推进指令时，必须先检查最新 CI 状态、失败日志、代码状态和文档同步状态；发现失败先修复，不得在失败上继续堆新功能。CI 处于 queued/running 时不得称为通过；只有当前提交检查完成且结果明确，才能进入下一步。


## 2026-10-08：重新分析闭环提交检查
重新分析闭环代码的测试修复同步完成：本次仅修正测试文件中的误写内容，并同步本记录以满足代码与帮助文档同提交更新的强制规则。后续继续推进前仍必须以最新 HEAD 的 CI 结果为准。


## 2026-10-08：重新分析保护当前成片引用素材
重新分析实拍素材时，系统现在会读取当前项目已有 Shot 的 `source_file` 以及已保存 `footage_plan` 中的来源文件。即使新一轮视觉分析把这些素材判定为不可用，也不会自动移动到 `05_废片库`，而是记录为 `protected` 并继续保留源文件，避免“重新分析”破坏当前已经生成的分镜/成片引用。新的剪辑方案仍可在后续选择其他素材。


## 2026-10-08：重新分析历史留档
“重新分析实拍素材”现在会在覆盖上一轮视觉分析、覆盖率、缺口、任务和最终分镜前，把上一轮结果写入项目的 `footage-reanalysis-history/`。项目同时保存历史文件路径，避免连续补拍后只能看到最后一轮结果。


## 2026-10-08：分析历史查看
新增“🕘 分析历史”入口，可查看连续重新分析保存的历史快照，包括覆盖率、缺口任务和历史镜头数；该页面只读取本地 JSON，不触发新的 AI 调用。


- 2026-10-08：补充 UI 操作契约回归测试，确保关键功能持续存在可操作的按钮入口。


## 2026-10-08：全桌面项目 UI 操作硬闸门
UI 操作契约不再维护一份容易漏项的“关键功能固定名单”。所有标记为 `@ui_action` 的用户可执行功能都自动纳入检查：必须存在真实 Tkinter Button 入口且绑定到对应方法；以后新增任何用户功能，如果后端写好了却没有 UI 入口，契约测试会阻断。AI 修改桌面项目时必须先完成“功能实现 + UI 入口 + 可操作路径”三者闭环，而不是只验证代码存在。

- 2026-10-08：修复全项目 UI 操作注册改造引入的嵌套弹窗保存回调缩进问题；`@ui_action` 仅用于 App 用户操作方法，不标记弹窗内部局部回调，避免破坏 Python 作用域。
