# 固定实施路线图、任务登记与进度计算

版本：2.2（自研实现、中国儿童体验、既定功能全部保留）
核心目标：不是做一个会回答数学题的聊天网页，而是建立可验证的学习闭环，帮助孩子独立掌握北师大版小学二年级数学知识，并诚实测量进步。
范围冻结：仍为 32 项、总权重 100%。用户已明确批准时间效率与试卷拍照为首期强制目标；本版本将其映射到现有 32 项任务，不增加分母，任务权重总计仍为 100%。其他新想法仍需变更审批。

## 1. 项目成功定义
系统必须能够回答并给出证据：
1. 孩子当前独立掌握哪些知识点，证据是什么？
2. 错误可能源自哪里，诊断依据和不确定性是什么？
3. 系统根据诊断采取了什么教学动作，为什么选择它？
4. 教学后孩子能否在无提示情况下独立完成不同题目？
5. 一段时间后孩子是否仍然记得，能否迁移到新题？
6. 单元、期中、期末的可比测评是否显示真实变化？
7. 若没有进步，系统是否调整教学、补查前置知识并再次验证？
产品交付、软件测试通过和孩子学习进步是三种不同状态。不得把上线、练习正确率、AI 自评或 CI 绿灯当作学习效果证据。

## 2. 执行纪律
- 每轮开始先读取接手文件、路线图、看板、验收标准、教学协议；查询最新 HEAD、PR、CI、部署状态和现有代码证据。
- 先向用户说明本轮唯一任务、范围和验收条件，再执行。
- 先检查是否已有能力，再决定复用、适配或开发；不重复实现。
- 每轮结束更新看板、任务登记、变更日志和接手文件；状态区分成功、失败、进行中、未运行、阻塞。
- 只有可复查的代码/测试/人工验收证据才计入进度。文档更新、提交、CI 绿灯均不自动等于功能验收。
- 不修改 apps/ad-studio-desktop/；不自动合并 PR。
- 上游正式许可证/授权未核实前，不复制或再分发其代码。
- 应用层不设置 Token 配额；技术故障重试必须退避且可恢复，不能无限重放请求。

## 3. 固定阶段与权重（32 项，总计 100%）

### P0 自研基础与设计系统（12%）
- MATH-001（4%）：全网参考调研与许可风险登记；记录框架、儿童 UX、OCR/视觉、教学设计和测试方法，不复制候选源码。
- MATH-002（3%）：验证自研技术栈与开发环境：Vue/TypeScript 前端、FastAPI 后端、SQLite、自动化测试和手机端路径。
- MATH-003（3%）：冻结自研架构与中国儿童视觉/交互设计系统，包括组件、颜色、字体、动效、语音、手机布局和隐私边界。
- MATH-004（2%）：建立独立应用骨架，跑通前端 build/test、后端 lint/test、基础 API 与持久化 smoke test。
不再要求先运行上游候选才允许开发；第三方代码/依赖/字体/图片/音效/教材内容仍需核查许可。

### P1 产品、教材与测量设计冻结（12%）
- MATH-005（3%）：冻结产品目标、首期范围、排除项、学生/家长流程与成功指标。
- MATH-006（3%）：核对实际教材版次、上下册、目录与当前进度；未核对映射标 draft。
- MATH-007（3%）：定义课程、题目、知识点、前置依赖、评估题组、证据事件的数据结构和版本规则。
- MATH-008（3%）：冻结教学诊断、提示、重做、掌握度、独立性渐进、延迟复测与评估公平性协议。
验收：需求、教学协议、课程计划、验收规则一致；测量设计先于分数结论。

### P2 云端 AI 与基础安全（15%）
- MATH-009（4%）：实现可配置 DeepSeek provider adapter；模型 ID 和 API base URL 不写死在题库。
- MATH-010（4%）：结构化输出校验、确定性校验优先、超时/限流/余额/API 错误的可恢复状态。
- MATH-011（4%）：密钥只在服务端；验证前端构建产物、浏览器请求和日志不泄露密钥。
- MATH-012（3%）：记录模型、用途、时间、状态和服务商返回的用量；不设应用层 Token 上限，故障退避有界且可恢复。
验收：受控/真实 API 测试有证据；不能把 API 失败伪装成教学成功。

### P3 教材映射与题目可信度（16%）
- MATH-013（4%）：选定项目的真实 loader/schema 与本项目课程格式一致；样例通过实际加载测试。
- MATH-014（4%）：首个试点单元完成教材映射、自编题、独立解法、分层提示和错误证据标签。
- MATH-015（4%）：确定性答案/算术校验、题意条件完整性、答案唯一性和年级适配检查可运行。
- MATH-016（4%）：AI 变式题审核工作流可运行；未经校验/审核的题不得进入学生练习或正式测验。
验收：自动校验与人工抽查分别留证；覆盖率按知识点覆盖和已验证题目统计。

### P4 诊断、教学调整与掌握验证（16%）
- MATH-017（4%）：三层提示（每题每回合最多 3 次）、完整讲解标记、原题延迟重做队列通过测试。
- MATH-018（4%）：错误诊断闭环：提出可检验假设、用鉴别题收集证据、记录置信程度；证据不足标 unknown。
- MATH-019（4%）：依据诊断选择教学策略，并验证策略调整是否有效；逐步减少不必要提示但不机械拒绝求助。
- MATH-020（4%）：知识点掌握证据、独立作答、不同题迁移、间隔复习和延迟复测完整运行；单次答对不代表掌握。
验收：覆盖误诊、连续错误、提示后答对、原题重做、迁移失败、延迟遗忘和前置知识缺口；系统必须能根据失败调整下一步。

### P5 学生端、家长端与可解释记录（12%）
- MATH-021（3%）：手机端学生流程可用，支持答题、可选提示、独立重做、变式练习和继续学习。
- MATH-022（3%）：家长报告呈现掌握证据、错误趋势、提示依赖、独立性、迁移、延迟保持和成绩变化。
- MATH-023（3%）：持久化答题事件、测验版本、复习队列、策略调整记录；导出/删除可验证。
- MATH-024（3%）：刷新、断网、API 失败、会话恢复与空状态通过测试；不得丢失关键状态或虚构完成记录。
验收：实际手机浏览器或等价设备测试；家长可追溯为什么系统认为会或不会。

### P6 集成、部署与安全验收（10%）
- MATH-025（3%）：自动化测试、静态检查、课程验证、学习状态机和测验逻辑测试通过。
- MATH-026（3%）：部署说明、环境变量示例、HTTPS/访问控制、持久化和备份/恢复说明完成。
- MATH-027（2%）：密钥、儿童隐私、错误状态、数据导出/删除和日志脱敏验收通过。
- MATH-028（2%）：新环境端到端测试：基线测验—练习/提示—诊断—教学调整—无提示变式—延迟复测—家长报告。
验收：保留命令、运行环境、版本、结果和人工步骤；只通过部署不算端到端通过。

### P7 学习效果验证与首期结论（7%）
- MATH-029（2%）：建立版本化测量蓝图、评分规则、基线/结束平行测验、延迟复测、迁移题和期中/期末累积测验。
- MATH-030（2%）：完成至少一个单元的基线与结束平行测验比较；分析分数、无提示独立性、提示依赖、错误类型和题目可比性。
- MATH-031（2%）：完成该单元延迟复测和迁移分析；验证未进步时的诊断—补弱—再测闭环；建立期中/期末流程。
- MATH-032（1%）：发布首期证据报告：已验收能力、未运行项、学习数据是否支持进步、测量限制和下一步措施。
验收：不预设必然提分或具体分数；未提升或数据不足时如实说明并执行补救/复测。学校考试与应用内测评分开记录。

## 4. 不可混淆的指标
### 软件交付进度
已验收任务权重之和 / 100%；同时显示已验收任务数 / 32。进行中、代码已提交但未验证、仅文档描述均不计入完成率。

### 学习效果
分开报告基线、结束平行测验、延迟复测、无提示独立完成率、提示使用分布、迁移表现、错误类型变化、前置知识缺口及测验条件。样本不足或题组不等价时明确标注。

### 教学闭环有效性
记录每次诊断假设、证据、教学策略、后续独立表现、延迟表现和是否调整。若孩子连续失败，系统必须换策略或检查前置知识，不能无限重复同一种提示。

## 5. 单任务执行卡
每项开始前记录 ID、目标、范围内/外、依赖、文件、验证步骤、通过条件、证据位置和状态。完成后记录实际结果、测试输出、提交 SHA、未解决问题。缺证据标未运行/阻塞，不猜测。

## 6. 范围变更控制
首期以 PRODUCT_SPEC.md 为准，技术以 TECHNICAL_ARCHITECTURE.md 为准，教学以 AI_TUTORING_PROTOCOL.md 为准，课程以 CURRICULUM_PLAN.md 为准，验收以 ACCEPTANCE.md 为准。新想法先进入后续候选；发现必要遗漏时先说明证据、影响和变更提议，只有用户批准新版本后才调整任务/权重。

## 7. 后续候选（不计入当前 32 项）
原生客户端、多孩子/班级、语音交互、更多年级/出版社、其他 AI 厂商、学校/教师端和长期教育效果研究。试卷拍照/手写识别已由用户明确纳入首期强制范围，不再列为后续候选。

## 8. v2.1 首期强制实现矩阵（纳入现有 32 项，不增加分母）

用户已明确批准将“尽量少的学习时间获得真实掌握”与“拍照上传真实试卷并辅导”列为首期必须实现目标。以下为现有任务的强制验收映射，不是后续候选，也不另增任务 ID。原有 32 项及权重合计 100% 保持不变；每项只有完成原有要求及下列适用的强制验收后才能验收。

- MATH-005：产品范围包含时间上限、学习任务排序、掌握后减量、三种试卷状态和家长可解释报告。
- MATH-007：数据契约覆盖每日任务目的/优先级/预计时长、试卷状态、图像识别置信度、人工确认、学生答案/过程、老师批改/分数来源、题目/图片关联。
- MATH-008：教学协议明确时间上限不等于最低学习时长；空白卷独立作答、已作答未批改卷保留原始表现、已批改卷分析错题；三者共用诊断与复测闭环。
- MATH-010：识别/API/结构化输出失败有可恢复状态；低置信度内容不得自动评分、诊断或更新掌握度。
- MATH-013：课程 loader/schema 可承载试卷解析后的题目、图表/符号、答案、批改、来源和知识点映射。
- MATH-015：加入图像识别确认、评分来源隔离、题目结构验证与防止 OCR 错误传播的测试。
- MATH-016：照片题经校验后才能进入练习/正式测验；识别不确定和题目质量不合格时阻止静默使用。
- MATH-018/MATH-019：以试卷作答证据诊断；策略无效后系统实际切换策略或回查前置知识。
- MATH-020：掌握后降低任务频率；复习队列结合时间上限排序；错题、迁移和延迟复测证据保持区分。
- MATH-021：手机端支持上传多页照片，并覆盖 blank、student_answered_ungraded、teacher_graded 三种状态及对应分流。
- MATH-022：家长端可见任务优先级理由、学习耗时、未掌握/稳定掌握知识点、试卷识别确认项、老师分数与系统测评的区分、策略调整和测量限制。
- MATH-023/MATH-027：原图/识别文本/手写作答/批改痕迹访问隔离、保留、导出和删除均可验证。
- MATH-024：刷新、断网、识别服务失败或中断后能恢复上传、人工确认、作答与复习队列；不得重复提交造成虚假成绩。
- MATH-028：端到端覆盖：试卷拍照→质量检查/确认→结构化题目→独立作答/错题分析→诊断→教学→无提示验证→重做/延迟复测→家长报告；另验证时间上限、掌握后减少练习和无效策略切换。
- MATH-029–032：真实学习效果分析必须报告学习时间、无提示独立表现、迁移、延迟保持、提示依赖和学校成绩；不能用刷题数量、在线时长或 AI 自评代替效果。至少覆盖一次“无提升→调整→补弱→再测”的实际流程。

### v2.1 强制验收门槛
1. 三种试卷状态各有自动化分流测试；识别低置信度必须请求确认。
2. 空白试卷在孩子作答前不展示答案；老师批改分数和系统测评分开存储、展示。
3. OCR/视觉错误不得静默传播到分数、诊断或掌握状态。
4. 每日时间上限可配置且有行为测试；达到上限后不启动新任务，未完成任务可顺延恢复。
5. 已稳定掌握知识点在同等条件下练习优先级降低；高价值前置缺口、反复错误和到期复测能影响排序，且理由可解释。
6. 教学策略连续无效时，后续状态/动作必须实际变化；仅生成“建议换方法”的文字不通过。
7. 每个行为必须有测试或明确人工验收步骤和证据；没有运行证据一律未验收。
8. 本次只是计划范围和验收规则更新；不增加任何已验收任务数或完成率。

## v2.2 自主单元选择与数学可信度验收映射（不增加任务分母）

- MATH-007：课程/题目数据契约必须表达册次、单元、主要/相关知识点、前置依赖、练习目的、难度、题目版本和来源；自主练习范围与老师作业范围分别记录。
- MATH-008：教学协议必须允许暂停、跳过、返回旧单元、重学和探索；AI 对前置知识的建议不能成为强制锁定；未选择单元不得静默混入。
- MATH-021：手机端提供单单元、多已学单元组合、全部已学累计复习、当前/旧单元比例、自主练习/老师作业分流和清晰的练习范围摘要。
- MATH-025：自动化测试覆盖单元筛选边界、跨单元混合与单题综合的区别、前置知识提示不锁路径、老师作业范围不扩张、题目正确性/不确定性处理。
- MATH-014/MATH-015/MATH-016：课程内容和 AI 变式题需检查年级适配、条件充分性、答案正确性与歧义；不能把系统题目错误归因于孩子。
- 验收方式：对每种选择模式检查生成题目元数据与实际题目集合；测试未选单元不出现、孩子明确加入后才出现、刷新后选择/进度可恢复。没有实际代码和测试证据时保持未验收。
