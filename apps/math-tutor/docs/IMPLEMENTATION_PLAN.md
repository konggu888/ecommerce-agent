# 固定实施路线图、任务登记与进度计算

版本：1.1（经用户确认补充提示管理与成绩目标）
状态：计划基线已更新；阶段 0 完成并经证据确认前，不进入应用实现。
范围变更规则：开发过程中不因联想自动增加首期范围。新增想法先进入“后续候选”，不得改变当前任务、权重或分母；只有用户明确批准新版本计划后才能纳入。此版本把用户明确提出的提示规则、错题重做和单元/期中/期末成绩验证纳入原有任务，不增加任务总数或权重。

## 1. 执行纪律
每次接手先检查本文件、项目 README、选型记录、最新分支/提交、PR、CI 与已有代码证据；先报告本轮唯一目标和验收条件，再执行。不得重复实现已有能力；先查源码、测试与配置。每轮结束更新本文件、进度看板、任务登记、变更日志和接手说明。未运行的测试必须标记未运行。CI 成功不能替代运行验证、人工验收或学习效果验证。

## 2. 固定阶段与权重（总权重 100%）
每项任务权重固定；完成状态需有对应证据。任务百分比 = 已验收任务权重之和。正在做、代码已提交但未验证、仅文档描述均不计为已验收完成。

### P0 项目选型与上游许可（12%）
- MATH-001（4%）：核实 OpenMath 正式许可/授权；保存可复查证据。
- MATH-002（3%）：核对上游实际目录、启动方式、课程 schema、测试和模型调用源码。
- MATH-003（3%）：完成最多 3 个候选的统一比较（OpenMath + 最多 2 个回退候选），形成明确选择。
- MATH-004（2%）：在选定版本上成功运行基线命令/测试，或记录阻塞及有证据的回退决策。
验收：有来源链接/提交 SHA、命令和结果；许可证未确认不得复制上游代码。

### P1 产品与课程需求冻结（12%）
- MATH-005（3%）：产品需求、首期范围和排除项已书面冻结。
- MATH-006（3%）：核对孩子实际教材版本、上下册和目录；若未提供，明确标记课程映射未验收。
- MATH-007（3%）：完成课程数据 schema、掌握证据和题目来源状态规范。
- MATH-008（3%）：完成 AI 教学协议、错误标签、提示上限/重做规则和题目质量规则。
验收：文档互相一致；不得声称完整教材覆盖而没有目录映射证据。

### P2 云端 AI 与基础安全（15%）
- MATH-009（4%）：DeepSeek 后端 provider adapter 配置完成，模型 ID 可配置。
- MATH-010（4%）：结构化输出校验、错误处理、限流/余额/超时状态完成。
- MATH-011（4%）：密钥服务端存储；自动化测试确认前端 bundle/网络请求不泄露密钥。
- MATH-012（3%）：用量记录、故障退避、用量可见性完成；不设应用层 Token 配额。
验收：真实/受控 API 测试有证据；密钥只用测试密钥，绝不提交真实 key。

### P3 课程、答题与题目验证（16%）
- MATH-013（4%）：选定上游课程 schema 与本项目课程格式一致，现有 YAML 经真实加载器校验。
- MATH-014（4%）：首个试点单元完成教材映射、自编题、标准答案和分层提示。
- MATH-015（4%）：确定性答案/算术校验与题目结构检查可运行。
- MATH-016（4%）：AI 变式候选题的审核工作流可运行；未验证题不进入学生练习。
验收：课程加载测试、题目质量测试及人工抽查均有记录。

### P4 个性化辅导与掌握评估（16%）
- MATH-017（4%）：分层提示、每题每回合最多 3 次提示、提示后原题重做队列和逐步讲解完整流程通过测试。
- MATH-018（4%）：错误分类、鉴别题与诊断证据持久化完成。
- MATH-019（4%）：换问法、逆向、无关条件、迁移练习生成和验证完成。
- MATH-020（4%）：掌握度状态、间隔复习和延迟复测完成；原题重做、提示后作答、新题迁移和无提示测验分开统计。
验收：覆盖正确、错误、提示用尽、提示后答对、原题延迟重做、连续错误、迁移失败和延迟复测情境。

### P5 学生端、家长端与数据控制（12%）
- MATH-021（3%）：手机端学生核心流程响应式可用，包括提示次数显示、提示后重做和复习入口。
- MATH-022（3%）：家长报告显示知识点证据、错误趋势、提示依赖、各单元/期中/期末成绩变化和下一步补弱计划。
- MATH-023（3%）：学习记录持久化、导出和删除完成；保留测验题组版本与分数历史。
- MATH-024（3%）：断网、API 故障、刷新恢复和空状态体验完成。
验收：在实际手机浏览器或等价设备测试并保存结果。

### P6 集成、部署与安全验收（10%）
- MATH-025（3%）：自动化测试、静态检查和课程验证通过。
- MATH-026（3%）：部署说明、环境变量示例、HTTPS/访问控制和数据持久化完成。
- MATH-027（2%）：隐私、密钥、错误处理和导出/删除检查完成。
- MATH-028（2%）：从新环境按文档部署并完成学生到家长报告的端到端流程，包括一轮提示后重做和测验报告。
验收：命令、CI 结果、实际环境和人工步骤逐项记录。

### P7 学习效果验证与首期验收（7%）
- MATH-029（2%）：建立固定版本基线题组、单元基线/结束平行测验、期中/期末累积测验蓝图与评分规则。
- MATH-030（2%）：完成至少一个单元的结束测验并与基线按可比条件分析；保存分数、知识点和独立答题变化。
- MATH-031（2%）：完成单元延迟复测、迁移题分析，并建立期中/期末模拟测验分析流程；记录未提升时的补救策略。
- MATH-032（1%）：完成首期验收报告，明确各单元/阶段成绩变化、已完成、未完成、数据限制和后续补救计划。
验收：不预设必然提分或具体分数；若未提升必须如实报告并执行补弱复测，不能把“上线”说成“成绩已提升”。单元、期中、期末测验都必须有可追溯题组版本和评分规则。

## 3. 进度看板格式
总进度必须同时显示：
- 计划权重完成率（仅已验收任务）；
- 任务计数（已验收/总任务）；
- 当前阶段和阻塞项；
- 最近一次测试/CI 的结果、提交 SHA 和时间；
- 未运行、失败、进行中、成功分别列出。
学习效果另行显示：各单元基线/结束/延迟复测，期中/期末模拟成绩，独立答题、提示依赖、迁移表现。产品开发完成率与学习提分结果不得混为一个百分比。
禁止用代码行数、文件数量、AI 自评或单纯 CI 绿灯代替完成率。

## 4. 单任务执行卡
每项任务执行前记录：ID、目标、范围内事项、明确不做事项、前置依赖、预期文件、验证命令/步骤、通过条件、结果证据、状态。完成后更新登记和看板。遇到缺少关键事实时先做有界核查；不可验证时标记 blocked，不擅自猜测。

## 5. 范围冻结与变更控制
- 当前首期范围以 `PRODUCT_SPEC.md` 为准。
- 技术边界以 `TECHNICAL_ARCHITECTURE.md` 为准。
- 教学逻辑以 `AI_TUTORING_PROTOCOL.md` 为准。
- 课程内容以 `CURRICULUM_PLAN.md` 为准。
- 密钥、用量和隐私以 `PRIVACY_AND_COST.md` 为准。
- 验收以 `ACCEPTANCE.md` 为准。
- 任何新需求先记入后续候选列表并说明成本/依赖，不得直接插入本轮开发。
- 如发现计划遗漏关键必需项，先写明证据、影响和建议变更；必要时更新计划版本，禁止边写代码边扩大范围。
