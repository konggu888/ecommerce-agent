# 技术架构与复用策略

版本：2.0（支持可验证的教学闭环）

## 1. 最高原则
优先验证并复用成熟开源数学辅导项目；只开发真实缺失的最小适配层。选型和许可证门禁未通过前不复制源码、不开始应用实现。架构必须支持诊断证据、教学策略、独立验证、延迟复测和测量报告，而不只是聊天记录。

## 2. 选型门禁
核实候选的正式许可证/作者授权、真实运行和测试命令、课程 schema、答案验证、提示、进度持久化、模型调用、手机 UI 和维护状态。OpenMath 为第一候选；不合格时最多再评估两个候选，总数不超过三个。许可证未确认前不得复制或再分发源码。

## 3. 目标逻辑分层
- Presentation：学生手机界面、家长报告、可访问性与恢复流程。
- Learning orchestration：学习状态机、诊断流程、策略选择、提示、原题重做、间隔复习和独立性渐进。
- Curriculum domain：教材映射、知识点和前置依赖、题目、标准解法、误区、测验蓝图。
- Deterministic validation：算术/答案、结构、条件完整性、答案唯一性、版本化测验评分。
- AI provider adapter：DeepSeek 首选；模型 ID、base URL 和密钥配置与题库分离。
- Evidence store：原始作答、提示事件、错误假设及证据、教学策略与结果、掌握证据、测验版本/成绩、复习队列。
- Evaluation/reporting：可比测验分析、独立答题/提示依赖/迁移/延迟保持指标、限制说明。
- Operations：部署、用量、错误监控、备份、导出和删除。

## 4. 教学闭环数据契约
至少能追溯以下链路：题目版本 → 学生作答 → 诊断假设（标签/证据/置信度）→ 鉴别题（如需要）→ 教学策略（原因/预期改变）→ 无提示变式结果 → 延迟复测结果 → 策略有效性 → 掌握证据。
诊断假设和学生实际作答必须分开存储。策略失败时记录调整原因。掌握状态不能只存一个没有证据的数字。

## 5. 测量设计
- 评估题组、蓝图、评分规则和知识点映射均需版本化。
- 单元基线与结束测验使用不同题目、同一蓝图和尽量相当的难度分布。
- 延迟复测和迁移题独立记录；期中/期末覆盖对应阶段已学单元。
- 报告呈现题组版本、样本数、分数变化、无提示表现、提示依赖、迁移、延迟保持和测量限制。
- 学校正式考试是外部结果，不能被应用测验替代，也不能在无证据时归因于单一教学策略。

## 6. DeepSeek、Token 和稳定性
- 服务端 provider adapter 读取密钥；浏览器不得直连供应商。
- 不设应用层 Token 配额/预算上限；按实际用量计费，记录服务商可返回的用量和调用用途。
- 结构化输出需 schema 校验；题目需独立校验，AI 自检不能自证正确。
- 超时、限流、余额不足、格式错误等必须返回真实状态；技术故障采用退避和可恢复重试，避免无限重放，不得伪装为教学完成。
- 正常教学可按需要多轮推理，不因 Token 用量主动截断。

## 7. 儿童隐私和数据
只收集完成学习闭环所需的最少信息；学习记录默认私密。提供真实可验证的数据持久化、导出和删除；启用 HTTPS/访问控制，日志脱敏，不记录密钥。课程数据与个人学习数据分离。

## 8. 架构验收
- 实际目录/源码与架构文档一致。
- 密钥不在前端构建产物、浏览器网络请求或日志中。
- 成功/格式错误/超时/限流/余额错误均有测试。
- 刷新或重启后答题、诊断、复习队列和测验历史仍存在。
- 可从一次错误追溯诊断证据、教学策略、后续独立验证、延迟结果和掌握状态变化。
- 手机端跑通基线—教学—独立变式—复测—家长报告链路。
