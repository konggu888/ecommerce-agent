# 技术架构与复用策略

版本：1.0（计划基线）

## 1. 最高架构原则
先验证并复用成熟开源数学辅导项目。不要因为本项目目录已建立，就默认从零开发；也不要因 OpenMath 是首选，就在授权、技术栈或手机可用性不合格时强行采用。只在确认现成能力缺失后，开发最小必要适配层。

## 2. 选型门禁（阶段 0）
按以下顺序检查 OpenMath：
1. 许可：正式 LICENSE、仓库元数据、文件头和作者许可是否一致；未确认前不得复制/再分发源码。
2. 可运行性：按 README 的实际步骤确认依赖、启动命令和测试命令；记录未运行项目，不推断成功。
3. 架构：检查课程 schema/加载器、提示生成、答案验证、学习进度持久化、用户界面、模型调用的真实源码。
4. 云模型：判断 Ollama 是否为硬依赖；确定是否能通过配置接入 DeepSeek 兼容 API，或通过独立 provider adapter 实现。
5. 移动端：检查核心流程在手机视口下是否可用；列出已有和缺失项。
6. 测试：确认课程验证和业务测试可执行，记录当前基线。
7. 复用决策：逐项标记“直接保留 / 小幅适配 / 必须新建 / 不复用”，给出文件与测试证据。

### 固定回退规则
若 OpenMath 许可不能核实或关键能力不满足，最多再评估 2 个成熟候选项目（总候选最多 3 个）。统一按许可明确性、课程数据可编辑性、提示/答题/进度功能、云 API 适配、手机可用性、测试和维护活跃度比较。完成比较后选最高分候选；如果都不合格，才批准开发最小缺失层。禁止持续无边界搜索。

## 3. 目标逻辑分层
具体目录以最终选定的上游项目为准，概念边界如下：
- Presentation：学生学习界面、家长报告、移动响应式布局。
- Learning orchestration：学习流程、分层提示、错误诊断、复习安排。
- Curriculum domain：教材映射、知识点依赖、题目、标准解法、误区和变式约束。
- Validation: 确定性算术求解/答案校验、题目结构校验、题意完整性和歧义检查。
- AI provider adapter：统一调用接口；DeepSeek 为首个 provider；模型 ID、base URL、请求超时等配置与课程内容分离。
- Persistence：学生、答题事件、提示事件、错误假设、掌握证据、复习计划、家长报告和调用用量。
- Operations：部署配置、日志、错误监控、备份/导出/删除。

## 4. DeepSeek API 适配
- 默认采用 DeepSeek 官方 API；兼容 OpenAI 格式的调用必须以 DeepSeek 当前官方文档和真实 API 测试为准。
- API Key 只在服务器端读取环境变量/密钥存储，前端只能调用本项目自己的后端。
- provider adapter 至少区分：生成教学提示、分析作答、生成候选变式题、复核题目、总结家长报告。
- 不把模型 ID 固定在 YAML 题库；通过环境变量/服务器端配置选择，使用账户实际支持的模型名称。
- 记录 request_id（如返回）、模型、耗时、输入/输出 Token（如返回）、目的和状态；不记录 API Key。
- 对模型输出使用结构化 schema 校验；失败时进行有限的格式修复/重试，并在无法恢复时清楚提示，不保存为已验证题目。
- 不允许浏览器直连供应商 API，不允许把密钥发给学生设备。

## 5. 数据存储与部署
- 先确认上游已提供的持久化能力并优先复用，避免平行重复实现。
- 需要持久化的核心数据：学生配置、教材进度、题目/版本、答题事件、提示使用、错误诊断及证据、掌握状态、复习队列、AI 调用用量。
- 部署平台与数据库在选型门禁后确定；需支持 HTTPS、环境变量/密钥、持久化存储、备份、导出和删除。
- 课程题库与个人学习数据分离。禁止将个人答题数据写回公共题库。
- 首期单家庭使用可以简单化部署，但不能以无持久化临时文件冒充正式学习记录。

## 6. 稳定性与无限 Token 政策
- 产品层不设置 Token 配额、每题预算、每日/每月预算上限；按实际使用量付费。
- 记录用量，允许家长查看账单估算/提供商返回用量。
- 对网络错误、限流、超时提供清楚状态和退避重试；不自动无限重放同一失败请求。
- 教学推理可多轮进行；只有明确的服务故障或用户离开当前流程才暂停，并保存上下文。
- 不能把 API 限流、余额不足或模型不可用隐藏成“孩子已完成”或伪造答案。

## 7. 安全与隐私
- 只收集完成辅导所需的最少信息；首期避免真实姓名、生日、学校和精确位置。
- 学习记录默认私密；家长可导出和清除。
- 不将儿童学习数据用于公开训练或发送到未配置的第三方。
- 日志需脱敏；不记录密钥、完整敏感请求或不必要的儿童个人信息。
- 提供数据保留和删除说明；生产部署启用 HTTPS 与访问控制。

## 8. 架构验收
- 架构图和实际选定项目目录一致。
- DeepSeek API Key 在前端构建产物和浏览器网络请求中不可见。
- 通过模拟/测试调用验证 provider adapter 的成功、无效输出、超时、限流和余额错误。
- 重启部署后学习记录仍存在；导出/删除操作真实有效。
- 手机端完整完成一次练习并在家长端看到对应记录。
