# 自研技术架构与参考借鉴策略

版本：2.1（加入时间编排与试卷图片链路）

## 1. 最高原则
从头开发自有应用。全网开源项目仅用于研究和借鉴，不把某个上游代码仓库作为必须的底座，不因候选项目缺功能或许可证不清楚而删除既定功能。不得复制未核实许可的源码；第三方依赖和素材分别核查许可。架构必须支持诊断证据、教学策略、独立验证、延迟复测、试卷照片和测量报告，而不只是聊天记录。

## 2. 自研初始技术路线
- 前端：Vue 3 + TypeScript + Vite，手机优先响应式网站/PWA。
- 后端：Python + FastAPI，将 DeepSeek、图片/OCR、课程逻辑、任务编排和报告隔离为可测试模块。
- 私用持久化：先以 SQLite 落地，数据访问层保持可迁移；默认私密访问，不做注册、多租户、排行榜、广告或订阅。
- AI：DeepSeek provider 可配置 model/base URL；密钥只放服务端。图片/OCR 使用可替换 adapter，按真实测试选型，不假设单模型能正确处理所有手写数学/图表/批改痕迹。
- 以上路线需通过 MATH-002 技术基线验证后冻结；若某个技术选项失败，只替换实现手段，不删减产品能力。

## 3. 目标逻辑分层
- Presentation：学生手机界面、家长报告、可访问性与恢复流程。
- Learning orchestration：学习状态机、诊断流程、策略选择、提示、原题重做、间隔复习和独立性渐进。
- Curriculum domain：教材映射、知识点和前置依赖、题目、标准解法、误区、测验蓝图。
- Deterministic validation：算术/答案、结构、条件完整性、答案唯一性、版本化测验评分。
- AI provider adapter：DeepSeek 首选；模型 ID、base URL 和密钥配置与题库分离。
- Evidence store：原始作答、提示事件、错误假设及证据、教学策略与结果、掌握证据、测验版本/成绩、复习队列。
- Evaluation/reporting：可比测验分析、独立答题/提示依赖/迁移/延迟保持指标、限制说明。
- Operations：部署、用量、错误监控、备份、导出和删除。

## 4. 教学闭环数据契约
至少能追溯以下链路：题目版本 → 学生作答 → 诊断假设（标签/证据/置信度）→ 鉴别题（如需要）→ 教学策略（原因/预期改变）→ 无提示变式结果 → 延迟复测结果 → 策略有效性 → 掌握证据。
诊断假设和学生实际作答必须分开存储。策略失败时记录调整原因。掌握状态不能只存一个没有证据的数字。

## 5. 测量设计
- 评估题组、蓝图、评分规则和知识点映射均需版本化。
- 单元基线与结束测验使用不同题目、同一蓝图和尽量相当的难度分布。
- 延迟复测和迁移题独立记录；期中/期末覆盖对应阶段已学单元。
- 报告呈现题组版本、样本数、分数变化、无提示表现、提示依赖、迁移、延迟保持和测量限制。
- 学校正式考试是外部结果，不能被应用测验替代，也不能在无证据时归因于单一教学策略。

## 6. DeepSeek、Token 和稳定性
- 服务端 provider adapter 读取密钥；浏览器不得直连供应商。
- 不设应用层 Token 配额/预算上限；按实际用量计费，记录服务商可返回的用量和调用用途。
- 结构化输出需 schema 校验；题目需独立校验，AI 自检不能自证正确。
- 超时、限流、余额不足、格式错误等必须返回真实状态；技术故障采用退避和可恢复重试，避免无限重放，不得伪装为教学完成。
- 正常教学可按需要多轮推理，不因 Token 用量主动截断。

## 7. 儿童隐私和数据
只收集完成学习闭环所需的最少信息；学习记录默认私密。提供真实可验证的数据持久化、导出和删除；启用 HTTPS/访问控制，日志脱敏，不记录密钥。课程数据与个人学习数据分离。

## 8. 架构验收
- 实际目录/源码与架构文档一致。
- 密钥不在前端构建产物、浏览器网络请求或日志中。
- 成功/格式错误/超时/限流/余额错误均有测试。
- 刷新或重启后答题、诊断、复习队列和测验历史仍存在。
- 可从一次错误追溯诊断证据、教学策略、后续独立验证、延迟结果和掌握状态变化。
- 手机端跑通基线—教学—独立变式—复测—家长报告链路。

## v2.1 强制实现与验收约束

## 9. 必须实现的时间预算编排与试卷识别链路

### 时间预算与任务排序
新增/适配一个可测试的 daily learning orchestrator：输入家长设置的时间上限、当天已用时间、候选任务预计耗时、知识点掌握证据、近期错误、前置依赖、测评/复习到期状态；输出有序且受时间上限约束的任务队列。预计耗时是估计，不得伪装成精确预测。到达上限后不再开启新任务，当前必要交互可安全结束，未完成项可恢复并顺延。时间限制只约束孩子投入，不约束服务端 Token 用量或必要教学推理。
稳定掌握的知识点应降低练习优先级；高价值前置缺口、重复错误和到期复测应获得合理优先级。排序理由应能解释给家长查看。

### 试卷图片管线
图片上传 → 隐私/文件类型/大小校验 → 图像质量检查 → OCR/数学符号/手写作答/图表/批改痕迹识别 → 置信度与不确定项 → 人工确认 → 题目结构化和知识点映射 → 根据试卷状态分流 → 共享教学闭环 → 持久化证据与复测队列。
图片解析应定义 provider/adapter 边界，按实际评估选择合适的 OCR/视觉能力；不能假设 DeepSeek 单一接口可稳定解析所有手写数学和图形。无法识别或模型故障时保存草稿/可恢复状态，不生成虚构答案或分数。

### 数据契约和行为约束
- 每题/图片字段包括来源、题号、识别置信度、人工确认状态、答案/过程来源、老师批改来源、评分来源、知识点映射、题目版本和验证状态。
- 试卷状态必须显式区分 blank、student_answered_ungraded、teacher_graded；分流规则需在服务端或可信业务层执行，不能只依赖 UI 文案。
- daily task 包括目的、优先级理由、预计时长、知识点、到期原因和是否允许启动；状态可恢复。
- 将时间上限、图像识别低置信度、老师分数隔离、空白卷答案泄露、OCR 错误传播、复习队列和策略切换加入自动化测试。


## 2026-10-19 自研产品与中国儿童体验原则
采用独立实现，不再把开源候选的许可证、架构或现成功能作为开始开发的前置门禁。参考项目只用于提炼设计和技术经验，不直接复制其代码；任何第三方组件、素材、字体、音效和课程内容仍需单独核查许可。

建议的初始技术方向（可在 MATH-002/003 通过基线验证后冻结）：Vue 3 + TypeScript + Vite 的响应式/PWA 学生端；Python FastAPI 服务端，便于隔离视觉/OCR、课程逻辑和 DeepSeek provider；SQLite 起步的私用持久化存储，数据访问层保持可迁移；图像识别采用可替换 adapter，不假设一个模型能可靠处理所有手写数学、图表和教师批改。API Key 只在服务端，图片/学习记录默认私密并支持导出、删除和保留策略。

界面采用简体中文原生设计，参考中国小学课堂、家庭、文具、校园、日常购物、时间/人民币/长度等孩子熟悉的情境，但课程与数学内容以实际教材核验为准。风格为温暖、清晰、灵动、耐看；大字、强对比、可触控控件、轻量动效、可选普通话朗读、安静模式。趣味机制服务于概念理解，不依赖强制打卡、排行榜、过度动画或以速度/刷题量为核心的奖励。设计必须通过真实手机尺寸与儿童可理解性测试。

## 2026-10-20 架构决策：开发/测试与正式生产部署分离

用户明确决定：开发和测试阶段可以使用 GitHub 与免费数据库服务；正式上线时部署到用户自己的服务器。Netlify 不是必需依赖，不得因为 Netlify 的额度/部署限制而阻断代码开发、测试或正式部署规划。

- 代码与版本控制：GitHub。
- 开发/集成测试数据库：优先评估用户已有的 Supabase 免费项目；使用前必须核查项目状态、现有数据/表、权限与免费额度，禁止未经确认复用或覆盖其他业务数据。若云端测试数据库不可用，继续使用本地 SQLite 做确定性自动化测试，不把 Supabase 连接失败当成产品功能失败。
- 本地/CI：保留 SQLite 测试路径，测试数据隔离，不将个人或生产数据带入 CI。
- 正式生产：用户自己的服务器。后端、数据库、密钥、备份、HTTPS、访问控制和部署方式由生产服务器方案负责；不得把 Netlify 或 Supabase 托管作为生产运行的强制依赖。
- 可迁移要求：持久化访问必须经独立数据访问层；数据库 schema 与迁移应尽量使用可移植的 PostgreSQL 语义，避免依赖 Supabase 专有功能。若开发阶段使用 Supabase Auth/Storage/Edge Functions 等平台专有能力，必须先评估是否会妨碍迁移；优先把核心业务逻辑放在可部署到用户服务器的 FastAPI 后端。
- 安全边界：API Key/数据库管理密钥只能在服务端环境变量或 Secret 中；前端不得获得 service-role/管理员密钥。测试与生产配置、数据库和凭据必须分离。
- 这是一项部署/环境架构决定，不改变 32 项任务分母和权重，不代表已接入 Supabase、已完成迁移或任何任务已验收。下一步先核查已有 Supabase 项目是否适合安全地作为开发/集成测试库，再按 MATH-002/MATH-004 的既定范围推进。


## 2026-10-20 自托管运行骨架（当前仅用于烟雾测试）

- 新增 apps/math-tutor/Dockerfile 多阶段构建、docker-compose.yml、deploy/nginx.conf、runtime requirements.txt 与 SELF_HOSTING.md。前端由 Nginx 提供静态文件并将 /api 转发到内部 FastAPI；SQLite 使用持久化命名卷。
- Compose 默认只将 Web 绑定到宿主机 127.0.0.1:8080，FastAPI 不直接发布端口。这样可由宿主机反向代理接入，但当前应用没有登录/授权，不能直接开放公网。
- CI 应构建 backend 与 frontend 两个 Docker target；这只能证明镜像可构建，不等于容器已在用户服务器启动，更不等于生产安全验收。
- 正式公网发布前必须实现认证/授权、HTTPS、备份恢复、儿童数据保护和安全测试；用户服务器上的部署与恢复演练仍需真实环境证据。
