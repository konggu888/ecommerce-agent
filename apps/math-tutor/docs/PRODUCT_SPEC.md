# 产品需求规格：北师大版二年级 AI 数学家教

版本：1.0（开发基线）
状态：计划冻结；完成阶段 0 的项目选型门禁后才进入应用实现。
项目位置：`apps/math-tutor/`。本项目与 `apps/ad-studio-desktop/` 完全隔离。

## 1. 产品目标
为孩子提供可通过手机浏览器使用的中文数学辅导网站，以孩子实际使用的北师大版小学二年级教材为课程主线。复用成熟开源项目优先，不从零重写已有的课程加载、答题、进度等能力。通过基线测验、个性化教学、独立迁移测验和延迟复测，验证学习是否真正改善。

## 2. 成功标准
1. 学生能够独立完成从课程选择、答题、分步提示到查看反馈的完整流程。
2. 系统能记录答题、提示使用、错误分类、变式题表现和复习结果。
3. 错题会触发可验证的诊断流程，而不是只显示标准答案或泛泛解释。
4. 掌握度必须由多次、不同表述、无提示及延迟测验共同支持；一次答对不算掌握。
5. 家长能查看知识点掌握、常见错误、学习趋势和下一步建议。
6. 网页适配常见手机屏幕；网络/API 不可用时清楚显示状态，不伪造结果。
7. 每个已声明完成的能力均有测试或人工验收证据。CI 通过不等于产品验收通过。

## 3. 目标用户和模式
- 学生模式：简洁中文、单步问题、少量同时显示的信息、清楚的反馈、支持触屏。
- 家长模式：学习概览、知识点趋势、错题与错误模式、复习建议、数据导出/清除。
- 同一网站内切换；家长操作应有独立入口，避免孩子误删记录。
- 首期单家庭/单学生体验优先；数据模型保留未来多学生扩展能力，但首期不开发班级、社交、排行榜或商业订阅。

## 4. 学习流程
1. 首次使用：确认教材版次/上下册/当前教学进度；进行短基线测验。
2. 学习：先确定题目在问什么，再识别条件、数量关系、估计结果方向，最后列式和验算。
3. 作答：记录答案及过程信息；支持文字作答，选择题只作为辅助，不以猜选项判定掌握。
4. 反馈：正确时说明关键理由；错误时先给不泄露答案的分层提示。
5. 诊断：必要时通过鉴别题区分审题、概念、关系建模、计算、无关条件、逆向问题和表达错误。
6. 强化：围绕已验证的薄弱点安排基础、换问法、干扰条件、逆向问题、迁移题。
7. 复习：按掌握证据安排延迟复测；错题原题重做与新题迁移分开计分。
8. 报告：显示已掌握/初步掌握/尚未掌握及其证据和置信程度。

## 5. 教学原则
- 先引导思考，不默认直接给答案；孩子明确请求讲解或多次提示后，可逐层展开完整解法。
- 不把题目中的每个数字都拿来计算；无关条件题必须明确考查审题且避免歧义。
- 不将所有题都设计成陷阱；基础、巩固、易错专项和挑战题分层呈现。
- 错误类型是待验证假设，不是对孩子能力的固定标签。
- 不羞辱、不恐吓、不比较排名；鼓励具体策略和努力。
- 不夸大成绩提升效果；通过前后可比的测验数据报告变化。
- 所有新题在进入练习前须经过答案、条件完整性、唯一性、年级适配和提示质量检查。

## 6. AI 与 Token 政策
- 首选用户已有的 DeepSeek API；模型 ID、API base URL 和密钥均可配置，不把模型名写死在课程文件中。
- 不设置应用层的日/月 Token 配额、单次教学 Token 预算或因费用而降低教学深度的策略；按实际 API 使用量计费。
- 不为节省 Token 而跳过必要的诊断、讲解、题目复核或复测设计。
- 必须记录每次调用的模型、时间、用量（若提供商返回）、目的、成功/失败状态和关联学习任务，供家长了解实际用量。
- 技术故障重试与教学多轮对话分开：正常教学不因轮数或 Token 用量被应用主动截断；网络故障重试应有退避和明确报错，避免软件死循环无限重放请求。
- Token/API Key 仅存服务器环境变量或安全密钥存储；绝不进入浏览器 bundle、客户端日志、Git 历史或题库文件。

## 7. 首期范围（必须交付）
- 可运行的移动端友好网页及部署说明。
- 可配置的 DeepSeek 兼容 API 后端适配；密钥安全处理。
- 课程/题目结构校验、答案校验、分层提示、错误分类。
- 变式题生成与复核流程。
- 学生答题记录、知识点掌握证据、间隔复习。
- 家长学习报告、数据导出与删除。
- 课程导入/验证工具、自动化测试和可复现验收步骤。
- 北师大版二年级课程映射框架和经过校验的首批自编试点题。

## 8. 明确不在首期范围
- 不训练自有基础模型，不运行本地模型作为前置条件。
- 不做原生 Android/iOS 客户端；先交付手机浏览器可用的响应式网站，PWA 安装能力作为验收增强项。
- 不接入学校/教育局系统，不做班级、社交、排行榜、广告或付费订阅。
- 不自动抓取或复制整本教材；只使用经核对的知识点映射和自编题，尊重版权。
- 不保证特定分数提升；不以 AI 自评代替学生实际测验。
- 不在本项目中修改电商广告桌面应用。
- 不因开发中临时想到的新点子扩充首期范围；新增需求必须记录到后续候选清单，经过范围审查后才能纳入新版本。

## 9. 依赖和未决门禁
在应用编码开始前，必须完成：候选项目许可核验、现有技术栈/课程格式/测试方式检查、DeepSeek 接入可行性检查、手机网页可用性检查。OpenMath 是第一候选，不因预先选定而免于验证。若无法合法或合理复用，按 `IMPLEMENTATION_PLAN.md` 中固定的选型回退规则执行，不进行无限搜索。
