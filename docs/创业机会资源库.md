# 创业机会与可借力产品资源库

> 目标：从约人民币 10,000 元起步，在约 90 天内验证能否形成**月净利润不少于 5,000 元**的可持续业务。
>
> 原则：优先利用已经存在的产品、平台、供应链、分销/代理计划和成熟工具；不因发现需求就自行开发软件。没有真实客户、真实付款和完整成本证据，不得标记为已验证。
>
> 当前状态：资源库已建立；以下为初始条目。它们是研究线索，不代表已建立合作或已成交。

## 1. 证据与状态规则

### 证据等级
- **E0 — 线索**：搜索结果、宣传文案或未经核实的说法。
- **E1 — 官方/服务商公开页面**：可确认页面展示的功能、公开报价或政策；不能证明真实成交量或用户满意度。
- **E2 — 独立交叉验证**：多个独立来源支持关键事实，仍不等同于我方付费需求。
- **E3 — 我方真实验证**：有可复核的客户访谈记录、书面合作条款、真实付款/订单、成本和交付记录。

### 商业状态
- **待研究**：已发现产品/平台，合作模式、需求或经济账未验证。
- **待联系**：已确认可联系的官方渠道，但尚未联系。
- **已联系**：有联系记录；不等于对方回复。
- **合作条件已核实**：已取得可核实的代理、分销、API 或合作条款。
- **首单已成交**：有真实付款/订单凭证。
- **持续盈利已验证**：有多个周期的真实净利润记录。
- **淘汰**：关键条件不成立，记录淘汰原因，避免重复试错。

## 4. 当前商业假设（未验证）

### 假设 A：借助现有工具，向商家交付一个明确结果
不卖“AI 能力”，而是卖可验收的交付，例如商品资料整理、合规素材处理、订单异常排查或批量上架辅助。只有当商家愿意付费且工具/人工/获客成本后仍有利润，才继续。

### 假设 B：利用已有产品的合法渠道合作
优先寻找官方代理、分销、推荐佣金、API 合作或平台服务商计划。必须取得可核实条款；没有授权不转售、不冒充官方、不擅自转卖账号/API 密钥。

### 假设 C：使用成熟供应链做小批量实物测试
先核实采购成本、运费、平台费用、退货损耗、售后、竞争价格和获客成本。未完成成本核算前不囤货；公开零售价不能证明可盈利。

- 获客成本：
- 退款、售后及坏账预留：
- 单笔净贡献：
- 每月需要的订单量：
- 真实付款证据：
- 90 天目标可行性判断：

计算规则：
- 单笔净贡献 = 实收收入 − 工具/采购成本 − 平台费用 − 获客成本 − 交付人工成本 − 退款售后等可归属成本。
- 达到月净利润 5,000 元所需订单量 = 向上取整〔(5,000 + 每月固定成本) ÷ 单笔净贡献〕。
- 单笔净贡献不大于 0，或订单量明显超出可交付能力时，停止该方案。

## 6. 下一轮优先动作

1. 对 R001–R009 逐个核查官方合作/代理/分销/API/服务商政策；仅引用官方条款确认授权与费用。
2. 记录能否个人参与、是否要求营业执照、保证金、预付费用、最低销售额和结算周期。
3. 同时寻找平台内公开的真实用户评价、成交证据或独立来源；把挂牌价与成交证据分开记录。
4. 从有低启动成本、可在 7 天内尝试首单的候选中，选择不超过 2 个做小规模验证。
5. 每次尝试记录真实接触人数、回复数、明确需求数、报价数、付款数、退款数、交付耗时和净利润。
6. 如果没有真实付款证据，不把“用户感兴趣”“公开页面存在”或“AI 评估可行”计入验证成功。

### 工具采用规则
1. **先试用现成工具，再考虑开发。** 只有现有工具无法完成经付费验证的关键需求，才评估自建。
2. **先看真实数据源标记。** real/API 与 mock 必须分开；模拟商品、销量、供应商和趋势不得进入采购决策。
3. **核对许可证。** GitHub 可见不代表可以随意商用；每次实际使用前检查 LICENSE、依赖许可证、品牌/素材权利和服务条款。
4. **核算总成本。** 除软件价格外，记录 API Token、云服务、人工清洗数据、部署维护和客户支持成本。
5. **优先本地、低固定成本。** 验证阶段不为尚无付费用户的项目租服务器或开发 SaaS。
6. **工具价值以节省时间和提高交付质量衡量。** 记录实际节省的工时、错误率、客户反馈和单笔净贡献，而不是按功能数量判断。

### 9.2 必须使用的价格计算规则

每个工具建立两套账：

**A. 现金支出（实际支付）**
- 一次性：购买/授权、设备、部署、迁移。
- 持续性：月费/年费、API/Token、云主机、数据订阅、平台手续费。
- 交易性：每单佣金、支付费、退款损耗。
- 退出性：取消订阅、导出数据、迁移与删除数据的成本。

**B. 完整经济成本（即使没有付款也不能忽略）**
- 安装配置、数据清洗、人工复核、维护、客户支持所耗工时 × 合理时薪。
- 免费工具不等于零成本；开源工具不等于无需维护。
- 本地部署不等于没有成本，只代表可能不产生新增云服务账单。

**每单净贡献公式：**
`每单净贡献 = 实收金额 - 交易费用 - 工具/API分摊 - 数据采购/采集成本 - 交付人工成本 - 获客成本 - 退款售后预留`

**工具方案月度成本：**
`月总成本 = 固定订阅/主机/数据费 + API实际用量 + 交易性费用 + 人工维护成本`

**是否值得购买：**
`净节省 = 使用工具前的人工成本 - 使用工具后的人工成本 - 工具现金费用 - 新增错误/返工成本`

如果净节省不为正，或工具并未提升客户结果，不购买/不续费。

**90 天目标校验：**
- 每个候选都计算一次性启动现金支出、每月固定支出、单笔净贡献、盈亏平衡订单量。
- 在获得首批真实付款前，默认不新增服务器、付费 API 订阅、批量采购或广告预算。
- 价格记录要带“价格核验日期、计价单位、套餐限制、是否含税、是否有免费额度、来源链接”；价格变动时更新旧记录而非覆盖历史。

### 15.3 统一计算口径

为避免不同工具使用不同口径造成“假误差”，先在测试表写清楚：
- **净销售收入** = 商品实付收入 − 已确认退款金额（优惠归属、运费处理需按原始账单口径定义）
- **订单贡献利润** = 净销售收入 + 实际由买家承担且归商家的运费收入 − 采购成本 − 包装/履约成本 − 商家承担运费 − 平台及支付费用 − 可归因广告费 − 其他变动成本
- **贡献利润率** = 订单贡献利润 ÷ 净销售收入；净销售收入为 0 时不计算百分比，标记为“不适用”
- **工具误差** = 工具结果 − 手工基准；**相对误差** = 绝对误差 ÷ 手工基准绝对值。基准为 0 或接近 0 时只报绝对误差，避免误导。
- **月度净利润不等于订单贡献利润**：还要扣除固定订阅、人工、设备、租金、税费等；不得将单笔利润直接外推为可持续净利润。

### 17.4 当前资金约束下的筛选顺序

1. **先盘点官方免费资源：** 千牛可用功能、低价货源监测、商家后台导出、生意参谋可用权限、1688 样品与供应商沟通。

### 18.2 必须采用的 AI 素材成本算法

生成内容的成本不能只看“单次调用价格”，至少要算：

- **每件商品可用素材成本** =（生成调用费用 + 失败重试费用 + 素材优化费用 + 人工审核成本）÷ 最终通过审核的素材数。
- **每条可发布视频成本** =（所有视频生成费用 + 失败重试费用 + 剪辑/配音/字幕成本 + 人工检查时间成本）÷ 通过商品保真和平台规范审核的视频数。
- **商品保真通过率** = 商品颜色、结构、图案、规格、品牌标识等关键项均通过核验的素材数 ÷ 总生成素材数。
- **有效节省额** = 原人工制作成本 − AI 方案的总成本；必须把人工修图、重生成、审片与版权/授权成本计入。
- **月度回本点** = 工具月度总成本 ÷ 每件商品实际节省成本。若实际节省额小于或等于 0，就不能以“AI 提效”为由购买。

以官方 Aidge 1080p 刊例价 2.5 元/秒举例，10 秒成片的理论调用费为 25 元；若生成 4 次才得到 1 条可用视频，仅视频调用费可能达到 100 元。这个例子是价格公式演算，不是实测废片率。免费额度耗尽后的真实账单必须以控制台为准。

1. **商品图生产：** 白底图、抠图、换背景、模特上身、虚拟试穿、尺寸/细节图、商品图翻译和批量裁剪。

|---|---|---|
| 商品外观保真 | 对照原图逐项检查颜色、形状、图案、结构、Logo、规格 | 关键事实错误的素材不得发布 |
| 模特/场景效果 | 检查人物、光线、姿势、背景与目标受众是否合适 | 不能只按“好看”评分，还要检查商品是否被改造 |
| 画质与规格 | 记录真实分辨率、画幅、时长、压缩与水印 | 与平台发布要求相符；需要 1080p 时必须实测输出尺寸 |
| 成功率 | 记录总生成数、失败数、重试次数和最终可用数 | 用最终可用素材计算单位成本 |
| 单位成本 | 记录免费额度、调用费、积分、失败重试和人工修复时间 | 不把免费试用当作长期成本 |
| 商用与素材权利 | 查服务条款、生成内容权利、模特/肖像/字体/音乐授权 | 未确认授权的素材不得用于商业投放 |
| 生产效率 | 从整理输入到最终可发布的总耗时 | 与原流程耗时比较 |
| 平台合规 | 检查夸大功效、虚假场景、误导性商品展示、禁限用词 | 不以生成成功等同于可发布 |

### 18.5 当前推荐顺序

1. **先检查账户内官方免费额度：** Aidge 的商品图处理与视频生成额度、淘宝/天猫商家可用的星辰入口、开放平台免费透明图 API；记录每项到期日。
2. **用同一商品做小样对比：** 不购买年费、不批量生成，先确认商品保真、画质、输出限制和可用成本。
3. **再比较现成工具：** 将万相营造等现成服务加入对照；核实实际积分价格、商用授权与水印。
4. **验证真实客户问题：** 访谈国内卖家，确认他们真正需要的是主图、上身图、短视频、批量上新还是整套运营；不同需求对应不同成本和付费意愿。
5. **最后才决定是否开发：** 只有现成工具无法解决、且有真实客户反复付费的缺口，才进入自研计划。

**本节结论：** 阿里现成 AI 能力不仅包括图片和视频生成，还涉及商品信息、素材优化、智能巡检、客服和经营 Agent。对当前小资金创业，最佳策略是先利用可用的免费额度与现成工具，做同商品对照测试并计算“每条可用素材的真实成本”；不要因为拥有生成能力就默认值得自研或购买套餐。

## 21. 资源库记录规则（新增）

- 发现值得关注但尚未验证的服务/软件时，**先记录并明确标注“待核实/未实测”**，不要因为信息不完整就漏掉，也不要伪装成已验证。
- 每条资源尽量包含：名称、官方/源码入口、能力、目标用户、免费/开源/付费类型、许可证/商业使用限制、最近维护迹象、依赖/部署难度、隐私与数据外传风险、对国内电商的具体用途、下一步验证动作。
- 资源分组固定为：**免费/开源候选**、**官方平台内置能力**、**商业/付费参考**、**暂不适用/观察项**。商业项目可保留作价格对照，但默认不主动推荐购买。
- “免费软件”不代表生成成本为零；要单列模型 API、GPU/服务器、素材版权、人工审核与失败重试成本。
- “项目在 GitHub 上公开”不代表没有许可证限制。未发现明确 LICENSE 时，状态记为“许可证待核实”，不得假定可以商用或闭源改造。
- 研究要落到创业验证：每一批工具最后都要回答“它能帮助哪类国内卖家解决什么付费问题、现成方案能否满足、真实交付成本是多少、有没有理由自研”。如果答案未知，就写清楚未知和下一步验证，不凭空补结论。

5. **最终目标仍是创业验证：** 这些资源是为低成本解决国内卖家问题服务，而不是单纯收集软件。每轮核查都要缩小到可测试的工作流，并验证是否能节省成本、提高产出或形成客户愿意付费的交付。

## 23. 创业方向纠正：卖实体商品；AI/软件服务只作为低成本经营工具（2026-10-20）

### 23.1 核心商业模式（以用户最新澄清为准）

**目标是自己选品、采购/组织供货并销售实体商品，赚商品交易利润；不是开发软件产品，也不是主要给其他商家提供代运营、作图、剪辑、客服或其他服务。**

AI 作图、视频、选品分析、利润核算、客服、货源搜索等服务与软件，是我们用于降低创业成本、提高经营效率的工具。由于这些服务已经有许多专业公司在做，个人不应默认能靠重做同类工具取胜。后续应全网寻找性价比高的现成服务、免费额度、开源项目和平台内置能力，比较后直接使用；只有工具确实缺失时才考虑小规模自制辅助脚本，不将其作为主营业务。

### 23.2 经营目标与边界

- **启动资金假设：** 约人民币 10,000 元，必须保留周转与售后资金，不应一次性压在库存或付费软件上。
- **验证周期假设：** 约 90 天内验证产品是否有真实需求、可稳定供货、能产生正向贡献利润并具备复购/持续销售可能。
- **目标假设：** 第 90 天附近争取达到月净利润 5,000 元。该目标不是预测或保证，必须由订单、退款、广告、物流、平台费用、税费、损耗、人工与工具成本等真实数据验证。
- **平台范围：** 以中国国内电商为主，重点研究淘宝/天猫、抖音电商、拼多多、京东、1688 等平台及其国内供货链路；不把海外独立站作为默认主线。
- **资金原则：** 先研究、再小批量验证，避免先囤货；优先考虑低起订量、可小批量补货、退换货风险可控的供货方式。不得把供应商宣传销量或平台热度直接当成需求证明。
- **产品选择原则：** 不预先锁定服饰或任何单一品类。用数据比较毛利空间、竞争强度、同质化程度、退货率、破损/保质期、售后复杂度、运输成本、供应稳定性、平台限制与现金周转后再选。

### 23.3 选品筛选框架：先找适合小资金验证的实体商品

每个候选品类至少收集以下信息，并标明数据日期与来源：

1. **真实需求：** 平台搜索需求、成交/评价趋势、季节性、复购可能；区分公开数据、卖家自述和实际验证。
2. **竞争与差异化：** 价格带、头部品牌/店铺集中度、同款数量、低价竞争程度、内容与渠道门槛。
3. **供货条件：** 1688/工厂/批发商报价、起订量、打样费、交期、补货速度、样品质量、质量一致性和供应商资质。
4. **单位经济性：** 售价 − 采购成本 − 国内运费/包装 − 平台佣金/支付费用 − 促销/达人/广告成本 − 预估退货退款损耗 − 售后/损坏损耗 − 税费及其他成本。
5. **现金流：** 首批采购金额、资金占用天数、平台回款周期、退货资金冻结、补货所需现金。
6. **经营难度：** SKU 数量、尺寸/颜色复杂度、安装/使用指导、售后问题、易碎/易损、有效期与合规要求。
7. **可验证性：** 能否先买样品、拍摄/试用、少量上架或通过合规渠道做小批测试；明确成功指标与停止条件。
8. **平台合规：** 类目准入、资质、品牌/商标、产品认证、广告法、知识产权与平台禁售/限售要求。

不得只按“毛利率高”选品。高毛利但需求弱、退货高、竞争极强或需要大额备货的商品，可能比低毛利但周转快、复购稳定的商品更差。

### 23.4 工具与服务的定位：全网找高性价比现成方案

以下全部是经营工具，不是默认主营产品：

- **商品图与视频：** 抖店/即创、淘宝/天猫现成能力、阿里云 Aidge、开源 ClipForge/OneMix 等。优先试免费额度，再按最终可用素材成本比较。
- **选品与货源：** 1688 官方采购助手、平台趋势/商机工具、开放平台能力、供应商比价工具。重点检查真实采购价、起订量、交期与授权。
- **经营与利润：** 平台官方数据工具、电子表格、本地利润核算工具。先用真实但脱敏的订单/费用数据核算净利润。
- **客服与售后：** 平台自带客服/自动回复与现成工具；先测试错答、转人工、平台接入和收费规则。
- **商品信息与上架：** 平台内置标题/属性工具、批量导入导出与现成软件；自动发布/改价等动作须由用户明确授权并可撤销。
- **其他运营工具：** 物流比价、订单/库存提醒、评价整理、售后原因分析、竞品价格跟踪、库存周转和现金流表等。只要能减少实际成本或错误就纳入研究，不限于 AI 工具。

每个工具都应记录：官方/源码入口、免费与付费边界、实际资格、许可证、商用权利、数据权限、维护状态、学习成本、是否可替代、每月成本、实际节省金额及核实日期。来源不明的下载站不推荐；未实测的功能标注“待验证”。

### 23.5 90 天实体商品验证流程（初步框架，尚非执行结果）

1. **第 1 阶段：市场与供应链研究。** 建立多个候选品类池，收集国内平台需求、竞争、供货和合规证据；淘汰明显需要大库存、资质门槛过高或价格战严重的方向。
2. **第 2 阶段：候选打分。** 需求证据 20 分、单位经济性 20 分、竞争与差异化 15 分、低起订量/供应稳定 15 分、退货售后风险 10 分、现金周转 10 分、平台合规与可操作性 10 分。高风险合规问题可直接淘汰，不以总分抵消。
3. **第 3 阶段：样品核验。** 对入选商品核验质量、包装、规格、实物与宣传一致性、物流和供应商响应。样品不合格就停止，不因为已花样品费而继续投入。
4. **第 4 阶段：小额市场测试。** 只在平台规则允许的情况下，用有限 SKU 和可承受库存测试。设定预算上限、观察周期、目标转化/毛利、退货率及止损条件；不虚报销量或客户反馈。
5. **第 5 阶段：按真实订单复盘。** 将退款、广告、运费、平台费、包装、售后和库存损耗纳入，算出每单贡献利润与现金回收周期。只有数据支持时才补货或扩大投入。
6. **第 6 阶段：决定是否扩大。** 以连续订单表现、供货稳定性、复购/评价和实际净利润决定继续、调整或退出；不能因为到第 90 天就必须继续亏损商品。

### 23.6 下一步必须完成的研究产物

- 国内电商候选实体商品/品类清单，并附公开证据、数据日期和来源。
- 每个候选品类的供应链与小批量采购条件。
- 可复核的单位经济性表和不同售价/退货率/广告成本下的敏感性分析。
- 免费/低价经营工具矩阵，说明哪些值得直接用、哪些付费不划算、哪些资格待核实。
- 排名靠前的少数候选商品的风险清单、样品验证计划、预算上限与停止条件。
- 以真实证据逐步修订的 90 天计划与进度统计；研究阶段不能虚报为已卖出商品、已联系供应商或已获得利润。

**本节结论：** 主业是卖实体商品。AI、开源软件与平台服务是降本增效的工具箱，应优先全网寻找性价比高的现成方案，不与成熟服务公司正面竞争，也不把开发工具误当成创业终点。
