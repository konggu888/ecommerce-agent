# 创业机会与可借力产品资源库

> 目标：从约人民币 10,000 元起步，在约 90 天内验证能否形成**月净利润不少于 5,000 元**的可持续业务。
>
> 原则：优先利用已经存在的产品、平台、供应链、分销/代理计划和成熟工具；不因发现需求就自行开发软件。没有真实客户、真实付款和完整成本证据，不得标记为已验证。
>
> 当前状态：资源库已建立；以下为初始条目。它们是研究线索，不代表已建立合作或已成交。

## 1. 证据与状态规则

### 证据等级
- **E0 — 线索**：搜索结果、宣传文案或未经核实的说法。
- **E1 — 官方/服务商公开页面**：可确认页面展示的功能、公开报价或政策；不能证明真实成交量或用户满意度。
- **E2 — 独立交叉验证**：多个独立来源支持关键事实，仍不等同于我方付费需求。
- **E3 — 我方真实验证**：有可复核的客户访谈记录、书面合作条款、真实付款/订单、成本和交付记录。

### 商业状态
- **待研究**：已发现产品/平台，合作模式、需求或经济账未验证。
- **待联系**：已确认可联系的官方渠道，但尚未联系。
- **已联系**：有联系记录；不等于对方回复。
- **合作条件已核实**：已取得可核实的代理、分销、API 或合作条款。
- **首单已成交**：有真实付款/订单凭证。
- **持续盈利已验证**：有多个周期的真实净利润记录。
- **淘汰**：关键条件不成立，记录淘汰原因，避免重复试错。

## 4. 当前商业假设（未验证）

### 假设 A：借助现有工具，向商家交付一个明确结果
不卖“AI 能力”，而是卖可验收的交付，例如商品资料整理、合规素材处理、订单异常排查或批量上架辅助。只有当商家愿意付费且工具/人工/获客成本后仍有利润，才继续。

### 假设 B：利用已有产品的合法渠道合作
优先寻找官方代理、分销、推荐佣金、API 合作或平台服务商计划。必须取得可核实条款；没有授权不转售、不冒充官方、不擅自转卖账号/API 密钥。

### 假设 C：使用成熟供应链做小批量实物测试
先核实采购成本、运费、平台费用、退货损耗、售后、竞争价格和获客成本。未完成成本核算前不囤货；公开零售价不能证明可盈利。

- 获客成本：
- 退款、售后及坏账预留：
- 单笔净贡献：
- 每月需要的订单量：
- 真实付款证据：
- 90 天目标可行性判断：

计算规则：
- 单笔净贡献 = 实收收入 − 工具/采购成本 − 平台费用 − 获客成本 − 交付人工成本 − 退款售后等可归属成本。
- 达到月净利润 5,000 元所需订单量 = 向上取整〔(5,000 + 每月固定成本) ÷ 单笔净贡献〕。
- 单笔净贡献不大于 0，或订单量明显超出可交付能力时，停止该方案。

## 6. 下一轮优先动作

1. 对 R001–R009 逐个核查官方合作/代理/分销/API/服务商政策；仅引用官方条款确认授权与费用。
2. 记录能否个人参与、是否要求营业执照、保证金、预付费用、最低销售额和结算周期。
3. 同时寻找平台内公开的真实用户评价、成交证据或独立来源；把挂牌价与成交证据分开记录。
4. 从有低启动成本、可在 7 天内尝试首单的候选中，选择不超过 2 个做小规模验证。
5. 每次尝试记录真实接触人数、回复数、明确需求数、报价数、付款数、退款数、交付耗时和净利润。
6. 如果没有真实付款证据，不把“用户感兴趣”“公开页面存在”或“AI 评估可行”计入验证成功。

### 工具采用规则
1. **先试用现成工具，再考虑开发。** 只有现有工具无法完成经付费验证的关键需求，才评估自建。
2. **先看真实数据源标记。** real/API 与 mock 必须分开；模拟商品、销量、供应商和趋势不得进入采购决策。
3. **核对许可证。** GitHub 可见不代表可以随意商用；每次实际使用前检查 LICENSE、依赖许可证、品牌/素材权利和服务条款。
4. **核算总成本。** 除软件价格外，记录 API Token、云服务、人工清洗数据、部署维护和客户支持成本。
5. **优先本地、低固定成本。** 验证阶段不为尚无付费用户的项目租服务器或开发 SaaS。
6. **工具价值以节省时间和提高交付质量衡量。** 记录实际节省的工时、错误率、客户反馈和单笔净贡献，而不是按功能数量判断。

### 9.2 必须使用的价格计算规则

每个工具建立两套账：

**A. 现金支出（实际支付）**
- 一次性：购买/授权、设备、部署、迁移。
- 持续性：月费/年费、API/Token、云主机、数据订阅、平台手续费。
- 交易性：每单佣金、支付费、退款损耗。
- 退出性：取消订阅、导出数据、迁移与删除数据的成本。

**B. 完整经济成本（即使没有付款也不能忽略）**
- 安装配置、数据清洗、人工复核、维护、客户支持所耗工时 × 合理时薪。
- 免费工具不等于零成本；开源工具不等于无需维护。
- 本地部署不等于没有成本，只代表可能不产生新增云服务账单。

**每单净贡献公式：**
`每单净贡献 = 实收金额 - 交易费用 - 工具/API分摊 - 数据采购/采集成本 - 交付人工成本 - 获客成本 - 退款售后预留`

**工具方案月度成本：**
`月总成本 = 固定订阅/主机/数据费 + API实际用量 + 交易性费用 + 人工维护成本`

**是否值得购买：**
`净节省 = 使用工具前的人工成本 - 使用工具后的人工成本 - 工具现金费用 - 新增错误/返工成本`

如果净节省不为正，或工具并未提升客户结果，不购买/不续费。

**90 天目标校验：**
- 每个候选都计算一次性启动现金支出、每月固定支出、单笔净贡献、盈亏平衡订单量。
- 在获得首批真实付款前，默认不新增服务器、付费 API 订阅、批量采购或广告预算。
- 价格记录要带“价格核验日期、计价单位、套餐限制、是否含税、是否有免费额度、来源链接”；价格变动时更新旧记录而非覆盖历史。

### 15.3 统一计算口径

为避免不同工具使用不同口径造成“假误差”，先在测试表写清楚：
- **净销售收入** = 商品实付收入 − 已确认退款金额（优惠归属、运费处理需按原始账单口径定义）
- **订单贡献利润** = 净销售收入 + 实际由买家承担且归商家的运费收入 − 采购成本 − 包装/履约成本 − 商家承担运费 − 平台及支付费用 − 可归因广告费 − 其他变动成本
- **贡献利润率** = 订单贡献利润 ÷ 净销售收入；净销售收入为 0 时不计算百分比，标记为“不适用”
- **工具误差** = 工具结果 − 手工基准；**相对误差** = 绝对误差 ÷ 手工基准绝对值。基准为 0 或接近 0 时只报绝对误差，避免误导。
- **月度净利润不等于订单贡献利润**：还要扣除固定订阅、人工、设备、租金、税费等；不得将单笔利润直接外推为可持续净利润。

### 17.2 官方证据与需要特别注意的条件

- 淘宝开放平台的商家经营工具说明将第三方工具分为千牛商家应用和一站式电商后台，并列出商品/订单、铺货分销、内容生产、客服、ERP、财务对账和利润分析等类目；官方类目开放状态并不完全相同，因此不能假定任何人都能随意接入或上架。
- 淘宝开放平台官方文档介绍“千牛低价货源监测”：免费开放、监测同款低价代发货源并估算降本空间；其操作说明明确提示自动下单只生成待付款订单，付款仍需处理。
- 阿里巴巴开放平台列出商品管理、订单管理、流量推广、店铺装修、铺货分销等场景，也列出一件代发、订单回流、批量支付和自动发货等能力。它们是平台/服务生态能力，不等于所有功能都能无门槛免费使用。
- 淘宝开放平台关于生意参谋的说明提到基础功能大部分免费、部分高级功能收费，但该说明年代较早；当前费用与权限必须登录后复核。
- 阿里妈妈服务商规则可能包含企业资质、经营年限、业务能力和保证金等准入要求。对我们目前约 1 万元启动资金的试水阶段，不应把“成为广告服务商/开发平台 ISV”误当成低成本首选。

### 17.3 从阿里生态中筛选创业机会，而不是盲目开发软件

**候选方向 A：淘宝/天猫店铺利润与货源降本诊断服务**
- 用商家授权的后台报表，核算 SKU 贡献利润、退款、运费、平台费用和货源成本；结合官方低价货源监测做人工复核。
- 收入假设：按店铺/按次收取诊断费，或后续提供月度复盘服务。
- 低成本验证：先找 3–5 位真实卖家访谈；取得明确授权和脱敏数据后，人工交付 1 份样例报告，再测试对方是否愿意付费。
- 风险：工具已有部分免费功能，单纯搬运报表没有付费价值；必须证明能找出可执行的降本/利润问题。

**候选方向 B：1688 货源筛选与样品验证服务**
- 针对一个具体类目，筛选供应商、比较同款规格/起订量/运费/交期/售后，购买少量样品验证后输出货源清单。
- 收入假设：筛选服务费、采购撮合佣金或后续运营服务；收费方式必须透明，避免虚假“官方合作”宣传。
- 低成本验证：先选一个窄类目，不囤货；用真实样品和供应商沟通记录建立证据。
- 风险：同图不同质、侵权/品牌授权、样品与批量货不一致、交期和退货问题。

**候选方向 C：淘宝联盟/内容推广的商品测试**
- 研究官方允许推广的商品、佣金条件和内容要求，用少量内容验证点击、转化和实际结算。
- 收入假设：按有效成交获取佣金。
- 低成本验证：不购买流量、不囤货，先验证内容生产与自然流量；必须记录实际结算而不是只看预估佣金。
- 风险：流量不稳定、佣金规则变化、退货导致佣金取消、内容制作耗时。

**候选方向 D：基于平台官方数据的店铺运营复盘**
- 把千牛/生意参谋/商家后台已有的数据整理成可理解的周报，提出商品、流量、转化和售后问题的具体行动。
- 收入假设：按次报告或月度服务收费。
- 低成本验证：先人工完成，不开发 SaaS；让卖家评价报告是否帮其节省时间或改善决策。
- 风险：免费官方工具已能覆盖基础数据；必须用清晰的诊断质量和执行建议证明额外价值。

### 17.4 当前资金约束下的筛选顺序

1. **先盘点官方免费资源：** 千牛可用功能、低价货源监测、商家后台导出、生意参谋可用权限、1688 样品与供应商沟通。
2. **再做人工服务验证：** 选一个窄问题（如利润核算、货源降本或店铺周报），先访谈卖家、做样例交付，验证真实付费意愿。
3. **再评估现成第三方软件：** 仅在官方能力不能解决问题时，比较服务市场的低价工具与实际节省时间。
4. **最后才考虑 API/开发：** 必须先有重复出现的真实客户需求，且人工流程已证明有效；将接口费、资质、服务器、安全、维护都计入成本。
5. **暂不进入高门槛服务商路径：** 不以阿里妈妈广告服务商、开放平台 ISV 或大型 ERP 实施作为当前第一步，除非后续资金、资质和客户证据支持。
