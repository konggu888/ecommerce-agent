# Ad Studio 阶段性验收计划

建立日期：2026-10-09。本文件是后续逐阶段验收的唯一工作台。每完成一项必须实际检查、记录；未通过不得默认进入下一阶段。

## 一、验收原则
1. 按阶段验收，不一次性判定全部完成。
2. 每项至少检查：功能存在、正常路径、异常/拦截路径、数据边界、回归测试。
3. 代码存在不等于功能验收通过；CI通过也不等于实际用户流程全部通过。
4. 发现问题记录“问题→原因→修复→回归检查”。
5. 不得为了通过验收而绕过安全闸门、伪造数据或降低检查标准。
6. 本计划当前覆盖投放前创意生产与成片交付；真实投放数据另列阶段。

## 二、投放前阶段

### A0 · 基础与工程稳定性
- [ ] 仓库结构与关键模块正常加载
- [ ] Python/前端语法检查通过
- [ ] Desktop核心测试通过
- [ ] Engine / Risk Controller / Typecheck通过
- [ ] 文档与代码同步机制正常
- [ ] 异常/无关内容扫描规则有效

### A1 · 素材分析与素材选择
- [ ] 原始素材可进入分析流程
- [ ] 可用/不可用素材判断明确
- [ ] 重复镜头、废片、最佳镜头等判断可追踪
- [ ] 不把未分析内容伪装成已分析
- [ ] 素材问题能进入后续补拍/补镜头决策

### A2 · 缺口判断与混合制作
- [ ] 商品证据缺口→继续补拍
- [ ] 真人口播/辅助视觉缺口→AI辅助画面路径
- [ ] AI生成不能冒充真实商品证据
- [ ] AI生成镜头默认待复核
- [ ] 人工通过后才能进入最终成片
- [ ] 预算/能力不足不会伪装成生成成功

### A3 · 广告创意多版本
- [ ] 可以生成多个创意版本
- [ ] 版本状态不会因切换方案丢失
- [ ] 不同版本有明确测试轴
- [ ] 多版本不自动等同于真实A/B投放结果
- [ ] 能识别单机制、多机制、仅表层、无明显差异

### A4 · 投放前创意分析
- [ ] 创意版本矩阵可查看
- [ ] 创意方案分析可解释版本差异
- [ ] 创意测试方案能输出测试目的→版本设计→观察目标→下一轮建议
- [ ] 不猜测抖音/淘宝/拼多多/小红书/京东
- [ ] 不凭空生成CTR/CVR/CPA/ROAS

### A5 · 创意事实与商品事实安全
- [ ] 商品卖点必须有商品资料依据
- [ ] 用户禁用词能够拦截
- [ ] 高风险绝对化表达能够拦截
- [ ] 缺少商品资料时明确提示无法核验
- [ ] 分镜事实检查不把文字检查冒充视觉检查

### A6 · 成片视觉事实检查
- [ ] 实际使用素材可映射到视觉分析
- [ ] 商品遮挡/模糊/抖动等风险可发现
- [ ] 不声称没有分析过的画面已确认安全
- [ ] 视觉风险进入最终安全闸门

### A7 · 最终安全闸门与媒体质检
- [ ] 创意事实风险阻止最终成片
- [ ] 视觉风险阻止最终成片
- [ ] AI生成镜头待复核阻止最终成片
- [ ] 输出存在且非空
- [ ] 视频流有效、时长有效、画幅符合要求
- [ ] 质检失败不会留下误认为可交付的坏文件

### A8 · 成片版本历史与交付中心
- [ ] 不同版本分别记录
- [ ] 不同画幅分别记录，不互相覆盖
- [ ] 可查看交付状态、时长、镜头数、文件存在性、路径
- [ ] 明确“可以交付/暂不能交付”
- [ ] 问题能定位到正确修复环节
- [ ] 支持一键重新检查
- [ ] 重新检查只使用已有资料和输出，不偷偷生成新素材

### A9 · 端到端投放前验收
完整走通：
素材进入→素材分析→缺口判断→补拍/AI补镜头→混合制作→多版本创意→创意分析→事实检查→视觉检查→安全闸门→媒体质检→成片历史→交付中心。
- [ ] 正常路径走通
- [ ] 商品事实错误可拦截
- [ ] 视觉风险可拦截
- [ ] AI镜头未复核可拦截
- [ ] 输出画幅错误可拦截
- [ ] 修复后从正确环节继续，不必全部推倒重来
- [ ] 最终得到明确可交付/不可交付结论

## 三、真实投放阶段（暂不验收）

### B1 · 真实投放数据基础
前提：用户明确指定平台并提供真实数据。
- [ ] 平台明确
- [ ] 数据来源明确
- [ ] 字段映射明确
- [ ] 真实数据与模拟数据严格分离
- [ ] CTR/CVR/CPC/CPA/ROAS只由真实输入计算
- [ ] 不跨平台臆测

### B2 · 平台适配
按实际需要逐个平台验收：
- [ ] 抖音
- [ ] 淘宝
- [ ] 拼多多
- [ ] 小红书
- [ ] 京东

### B3 · 真实投放反馈闭环
- [ ] 真实结果→创意版本
- [ ] 结果解释有数据依据
- [ ] 下一轮测试建议有明确依据
- [ ] 不把模拟对手行为写成真实竞争对手行为

## 四、每次验收固定记录
阶段｜日期｜检查范围｜正常路径｜异常路径｜数据边界｜自动化测试｜发现问题｜修复提交｜回归检查｜最终结论｜下一步。

结论只允许：**通过 / 有条件通过 / 不通过**。

## 五、执行顺序
A0→A1→A2→A3→A4→A5→A6→A7→A8→A9→最后才进入B1/B2/B3。

## 六、验收纪律
每完成一个阶段先停在该阶段给出结果；通过后再进入下一阶段。失败则优先修复，不跳过。所有修复必须重新跑相关测试。代码、HELP、PROJECT_LOGIC必须同步。本文件每次验收完成后更新对应状态、问题与修复提交。
