# 用户体验与产品安全完整性审查计划

版本日期：2026-10-15  
适用仓库：`konggu888/ecommerce-agent`  
适用项目：`apps/ad-studio-desktop`  
当前执行方式：静态文档/代码/测试审查，并对已映射到现有合同的可复现缺陷补充离线 mock 回归和最小修复；不启动真实环境验收。

## 1. 目的与边界

本审查用于回答：现有规划、代码、测试、UI、帮助文档和恢复机制，是否足以指导 AI 将桌面应用做成普通用户能理解、能安全操作、能恢复异常，并能获得符合明确质量标准的商业视频产品。

这不是另起一套路线图，也不是新增一批未经核实的验收编号。它是 PLAN-003 的完整性检查入口，先识别已有要求、重叠要求、缺口和证据不足，再将确有必要的独立要求映射回正式验收计划和总台账。

### 明确不做

- 不做未经合同映射的产品扩展；允许对已映射的既有合同补充离线 mock 回归与最小缺陷修复，不为增加任务数量而拆分任务。
- 不因本文建立就认定任何功能已实现、已验收或项目完成率提高。
- 不删除或重编号 A0–A112；发现同义项必须先保留原 ID 并建立映射。
- Windows 真机、真实素材、真实 Provider/实际扣费、剪映现场、真实投放和商业效果验证继续暂缓。
- PR #32 必须保持 Open / unmerged。
- 总体完成率、权重和 fully_audited 口径继续关闭，直到 PLAN-003 完成规定审计。

## 2. 审查的八个维度

1. **新手可理解性与可发现性**：首次打开、入口可见性、术语解释、默认路径、简单模式/高级设置边界、空状态和操作反馈。
2. **端到端用户旅程**：创建项目、商品输入与核实、目标/策略、预算确认、资产准备、分镜、逐镜头生成/修改、剪辑、质检、修复、交付、保存与再次打开。
3. **费用与外部副作用安全**：预估和确认时点、取消零调用、重复点击/重试、超时后结果不确定、账本失败、预估与实际费用差异、预算告警与用户选择。
4. **数据、素材与版本安全**：自动保存、崩溃恢复、备份/迁移、磁盘不足、损坏数据、项目隔离、版本隔离、路径变化、删除/覆盖保护、引用关系与资产可追溯。
5. **商品真实性、内容风险与交付闸门**：商品外观/结构/功能/用法事实边界、未验证声明、禁用/高风险表达、视觉复核证据有效性、交付文件完整性、1080P尺寸与真实清晰度区别。
6. **跨功能状态与依赖一致性**：修改商品/演员/场景/分镜/比例/音乐后，哪些下游结果失效、哪些可复用；任务并发、版本切换、状态机、稳定 ID 和旧结果隔离。
7. **异常解释与可恢复性**：错误归因、可重试性、恢复旧有效结果、部分成功、外部服务不可用、资源不足、退出/重启、人工决策与必须阻断的情况。
8. **结果可理解性与商业质量**：用户能看到阶段、待办、风险、费用、失败原因和下一步；同时区分运行正确、流程正确、商品表达正确、商业成片质量，不能用 CI 或分辨率替代主观/真实媒体验收。

### 本轮首个阻断发现的处理边界

- 不在本轮擅自修改产品代码；该项先作为 UXS-2 发现登记，并与 A0–A112 及用户既定费用授权合同对照，确认是否已有对应正式 ID/重复记录。
- 在明确的费用确认顺序得到证据前，不得把“费用明细弹窗存在”写成“费用闸门安全”。
- 由于实际模型路由可能包含本地或云端模型，当前结论是“规划模型调用发生在费用确认前；是否属于未经授权的收费云端调用，取决于既定授权范围和所选路由”，不是宣称每次都会产生实际扣费。
- 继续审查其他旅程段时，只记录证据和缺口；不因发现阻断项就顺手开发，也不把它降级为普通体验改进。

## 4. 风险等级与处置原则

- **P0 阻断性风险**：可能造成未经确认的费用/重复扣费、不可恢复数据丢失、跨项目或跨版本污染、危险/虚假商品表达被放行、损坏成片被标记可交付。必须先阻断或恢复安全状态。
- **P1 高风险缺口**：核心流程无法继续、用户无法理解费用/失败/风险、旧有效结果保护不足、关键状态不可追溯。应在依赖其上的阶段继续前处理或明确隔离。
- **P2 重要体验/质量缺口**：可绕过但明显增加误操作、困惑或产出质量不稳定。进入正式排期，需有验收标准。
- **P3 改进项**：便利性、说明文案或非关键效率问题。只登记，不顺手开发。

等级需依据可观察的损害、发生概率、可逆性、影响范围和现有缓解措施判定；不得仅凭主观严重感。未知证据标为“待核实”，不能直接标为安全或不安全。

- UI 可见反馈与帮助文档位置；
- 真实环境限制；
- 风险等级、正式任务 ID、重复/依赖映射和未决问题。

### 已发现的风险/缺口（待映射 A0–A112，不新增编号）

1. **P0 候选｜费用授权时点。** 已有 UXS-2 §3A 发现：`App.create()` 会在“AI创意与项目预算确认”弹窗之前调用 `create_plan/create_plans`；这些阶段可走收费云端模型。需先裁决既有合同对“所有收费云端 LLM 分析/规划调用”还是仅“视频/资产生成调用”的授权范围。不能把费用明细弹窗存在等同于调用授权安全。
2. **P1｜路由自动回退可能改变用户选定的模型/Provider。** `ModelRouter.resolve_route()` 在所选模型不可用时可按硬件策略改用其他云端模型或本地模型；`CapabilityRouter` 在本地服务不可用时也有转云端的决策分支。静态代码未证明每次跨 Provider/向云端传输前都要求单独、明确的用户同意。需核对 UI、配置开关、提示与现有 A0–A112 任务，并用调用计数测试证明用户拒绝回退时外部调用为 0。
3. **P1｜密钥明文落盘。** 模型配置通过 `ModelRouter.save()` 写到本地 JSON，`ModelProfile.public()` 的遮挡不影响保存的数据。需要查明配置目录权限、备份/导出行为和项目迁移路径；当前未找到加密/系统凭据库证据。不得声称密钥已安全存储。
4. **P1｜费用估算可能低估。** 文本模型的估算依赖返回的 token usage 和用户配置的单价；默认单价为 0。若代理不返回 usage、单价未填或供应商按请求/图片/缓存/最低消费收费，当前 Token 账本不能证明真实支出。需要明确“未知/未配置”与“免费/零成本”的区别，并以真实账单对账作为暂缓的外部验收。
5. **P1｜外发数据告知与端点安全待查。** 自定义 Base URL 会接收 prompt，启用视觉输入时图片会以 data URI 发送；视频 Provider 可携带参考素材路径或内嵌素材。当前所查代码未显示请求前的逐 Provider 数据外发说明，也未确认对 URL/重定向/私网地址的安全策略。需要把用户可理解的“将发送哪些数据、发送给谁、是否云端”作为审查点；不能默认用户只改了模型名就理解数据去向。
6. **P2｜“接入任意模型”不能按当前实现承诺。** 现有文本接口主要限于 OpenAI-compatible Chat Completions；Provider 字段虽然可编辑，但不代表任意 provider 值会被支持，`complete_json` 对未知提供方式会报错。专有 API、不同鉴权方式、不同多模态/结构化输出协议仍需要明确适配器或转换层。
7. **P2｜模型能力声明与实际能力可能不一致。** 图片输入依赖用户勾选 `vision_enabled`，转写依赖 `transcription_enabled`；静态配置/连通测试并不能证明模型真的支持对应能力或 JSON response format。需审查失败提示、能力探测、路由前能力校验与 UI。
8. **P2｜文本、图片、视频、语音接入自由度并不等价。** 文本模型池有 per-function routing；视频和资产生成走独立配置/通用 REST 适配器；不能将“文本模型可换”泛化成“所有生成阶段都可自由切换任意模型”。
9. **P2｜现有路由专项测试覆盖口径需校准。** `test_model_router.py` 中测试名称仍称“nine functions”，但当前 `FUNCTIONS` 有 13 个条目；需检查测试断言是否使用动态列表、是否真实验证所有 13 个阶段以及视觉/转写路径，不能只依据测试名称宣称覆盖完整。
10. **P2｜配置可迁移性/版本隔离待查。** 模型配置在本机数据目录，历史项目保存的模型标识、切换模型后的缓存键、输出追溯和导出/迁移行为仍需继续审查；当前静态证据不足以承诺换 Provider 后历史项目完全可复现或数据不被污染。

### 面向用户的准确结论

- **现在能做：** 通过界面配置多个 OpenAI 兼容文本模型；对功能分别指定模型；配置本地 OpenAI 兼容服务；在接口协议兼容的前提下接入自训模型服务或 Token 代理；独立配置部分通用 REST 视频/资产 Provider。

## UXS-2 路由回退专项证据映射｜2026-10-15（静态审查，非验收）

### 已核实的调用行为
- `ad_studio/model_router.py::ModelRouter.resolve_route()` 先读取功能的显式路由；若模型启用且凭据满足条件，就返回该模型。
- 若显式模型不可用，函数会读取硬件 `execution_mode`。当模式为 `cloud_first` 时，它会遍历模型池并返回第一个已启用、非 `local_openai` 且配置 API Key 的模型；否则/随后会选择第一个启用的本地模型；若仍没有可选项，返回原显式路由，之后调用阶段才可能报错。
- `ad_studio/capability.py::CapabilityRouter.decide_llm()` 在没有可用本地模型、但云端模型配置可用时，会给出“改用云端模型”的决策；资产和视频能力的 `decide_asset()` / `decide_video()` 也会在本地服务不可用时选择配置好的云端服务。

### 暂定风险结论（映射 A0–A112，尚未裁决是否有独立缺口）

### F. 继续核对：资产配置根目录与调用历史可追溯性

- `App.asset_generation_settings()` 固定读写 `ROOT/'asset-generation.json'`；但 `ProductionStore.resolve_assets()` 创建 `AssetGenerator(self.library_root/'asset-generation.json', self.library_root)`，而 `self.library_root` 可由 `library-location.json` 改为用户指定的独立磁盘路径。`AssetGenerator` 又从传入的 `config_path` 读取设置并以其父目录创建 `CapabilityRouter`。因此，当用户自定义资产库路径且该目录下没有同步配置文件时，UI 中已保存的资产生成设置与 `resolve_assets()` 实际读取的配置位置不一致，可能表现为“界面配置已保存，但自动素材生成看不到配置”。这是由路径数据流支持的静态缺陷候选；本轮没有执行真实生成。
- `generate_missing_asset()` 是另一条调用路径：它接受外部传入的 `asset_provider_path`，调用 `CapabilityRouter(self.root.parent).decide_asset(kind)` 决策，再用传入路径加载云端 Provider。必须把这条路径与 `resolve_assets()` 的 `AssetGenerator` 路径分开测试，不能因为一条路径可用就推断另一条可用。
- 生成历史可追溯性方面：文本模型 usage ledger 记录 `model_id`、`model_name`、`provider`、`model`，但不记录实际 `base_url/endpoint`；视频镜头的 `shot.provider` 和视频账本主要记录 provider 名称，视频/资产账本行的 `model_id`、`model` 为空。自定义代理站或同名 Provider 变更 endpoint 后，当前历史记录未必足以复原当时真实请求目的地。这是审计追溯缺口，不代表已有调用被错误路由。
- 缓存/镜头状态中也应区分“显示 Provider 名称”与“实际 model/endpoint”。下一轮需验证缓存命中、单镜头重生成、项目重载后是否保留足够的实际路由证据，且不把 API Key 写进历史记录。
